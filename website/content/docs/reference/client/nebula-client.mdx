The game client. Talks only to the gateway, sends inputs, receives snapshots tagged (tick, epoch, owner) and predicts its own player. It is never a party to the handover protocol: which worker produced a snapshot is metadata used for epoch filtering and the debug overlay, nothing else.

### SessionToken [#sessiontoken]

```csharp

```

The session token from the last Welcome ([`WelcomeMsg.SessionToken`](/docs/reference/protocol/welcome-msg#sessiontoken)), presented on every reconnection so the gateway that answers, whichever one of the mesh it is, gives this client its session and pawn back. Kept for the life of the process; [`Disconnect`](#disconnect) keeps it too, so a deliberate reconnect continues the session. Clear it to start a new session on the next connection.

### ScopeKey [#scopekey]


The simulation scope this client asks to be placed in, as the opaque key the game chose ([`EntityLocation.ScopeKey`](/docs/reference/containers/entity-location#scopekey)). Empty, the default, is the public world. Set it before connecting — a travel menu or a matchmaking reply hands the key over — and the gateway spawns the player into that scope's containers instead of the public ones. Seeded from `-nebula-scope`. Changing it takes effect on the next connection.

### FocusHint [#focushint]

```csharp
public Vector3? FocusHint { get; set; }
```

Where the player is looking, in this client's own Unity world space, when that is not simply where the pawn is: a free camera, an RTS view, a spectator. Set it and the client sends the gateway a [`ClientFocusHintMsg`](/docs/reference/protocol/client-focus-hint-msg) at up to [`NebulaConfig.InterestHintMaxHz`](/docs/reference/core/nebula-config#interesthintmaxhz), converting the point to absolute world coordinates on the way out ([`AbsoluteFocusHint`](#absolutefocushint)), so a floating-origin shift between two hints does not move the place the gateway thinks you are watching.

The gateway treats it as an input and never as authority: it is refused unless the server allowed this client a focus (`NebulaGateway.SetClientFocusMode`), and by default it is clamped to [`NebulaConfig.InterestHintMaxDistance`](/docs/reference/core/nebula-config#interesthintmaxdistance) of the pawn. A game cannot widen its own interest by lying about where it is looking.

### ContentAnchor [#contentanchor]

```csharp
public Transform ContentAnchor { get; }
```

What this client's **content** follows: which cells or chunks are kept loaded, and where the floating origin sits. Null (the default) means the local pawn.

A strategy game does not want that. Its camera flies over a front the commander has no pawn near — or has no pawn at all — and content anchored to the pawn would leave the camera looking at unloaded terrain however much the gateway is willing to send. Handing the camera's transform to [`SetContentAnchor`](#setcontentanchor) moves the window with the camera instead.

### Disconnected [#disconnected]

```csharp
public event Action<DisconnectInfo> Disconnected;
```

The connection to the gateway ended, or the first attempt to connect failed. The argument says why ([`DisconnectInfo.Reason`](/docs/reference/client/disconnect-info#reason)), with a readable message, and whether the client will try again by itself ([`DisconnectInfo.WillRetry`](/docs/reference/client/disconnect-info#willretry)). It is raised again, with [`DisconnectInfo.WillRetry`](/docs/reference/client/disconnect-info#willretry) false, when the client stops trying: a refusal, a replaced session, or [`Disconnect`](#disconnect). Raised on the main thread, after [`ConnectionStateChanged`](#connectionstatechanged).

## Methods

### ClearFocusHint [#clearfocushint]

```csharp
public void ClearFocusHint();
```

Withdraw the focus hint: interest returns to the pawn. Going quiet is not enough — the gateway keeps the last hint it accepted — so the clear is said out loud, reliably, under a new generation that makes any hint still in flight stale.

### AbsoluteFocusHint [#absolutefocushint]

```csharp
public void AbsoluteFocusHint(out double x, out double y, out double z);
```

[`FocusHint`](#focushint) in absolute world coordinates: the frame position with the floating origin of the local pawn's scope added back, in double, exactly as a worker resolves its own entities (`WorkerInterest.ToAbsolute`). A scoped chunk grid moves its own origin, not the public one, so the hint is converted through the scope's frame (`docs/scope-frames.md` D4b, NEB-338). Without a world definition or a scope frame the origin never moves and the two spaces are the same. All zero when there is no hint.

### SetContentAnchor [#setcontentanchor]

```csharp
public void SetContentAnchor(Transform anchor);
```

Anchor content to this transform — the active strategy camera, a selected unit, a cinematic rig — instead of to the local pawn. Pass null to go back to the pawn. It is deliberately a transform and not the focus hint: the hint is an optional, rate-limited, server-validated *request* about what to be sent, while the anchor is a local decision about what to keep in memory, sampled every frame so load/unload hysteresis and origin shifts have something continuous to measure against.

Both are usually the same place, and a game that drives a free camera normally sets [`FocusHint`](#focushint) to the camera's aim point and the anchor to the camera. Doing so is safe across an origin shift: the hint is converted to absolute coordinates as it is sent ([`AbsoluteFocusHint`](#absolutefocushint)), so moving the origin under the camera does not move the point the gateway thinks anyone is watching. The pawn's prediction is unaffected too — it reconciles in the same frame everything else is in, and an origin shift moves that frame for all of them at once.

### Disconnect [#disconnect]

```csharp
public void Disconnect();
```

Leave the gateway and stop reconnecting. The client stays idle until the next [`Connect`](#connect) or [`ConnectTo`](#connectto). To the server this looks like a lost link: the worker keeps the pawn for [`NebulaConfig.SessionReclaimSeconds`](/docs/reference/core/nebula-config#sessionreclaimseconds) so the player can come back to it. Use [`Leave`](#leave) when the player is leaving for good.

### Leave [#leave]

```csharp
public void Leave(float timeoutSeconds = DefaultLeaveTimeoutSeconds);
```

Leave the world for good: the player chose to quit, or to go back to the menu. Unlike [`Disconnect`](#disconnect), the session ends at once instead of waiting out [`NebulaConfig.SessionReclaimSeconds`](/docs/reference/core/nebula-config#sessionreclaimseconds): the client sends a goodbye, the worker calls [`NebulaGameMode.OnPlayerDespawn`](/docs/reference/core/nebula-game-mode#onplayerdespawn) and removes the pawn (a persistent pawn keeps its record), and other players stop seeing it. The session token is cleared, so the next [`Connect`](#connect) starts a new session.

The client is `State.Disconnected` when this returns and raises [`Disconnected`](#disconnected) with [`DisconnectReason.ClientRequested`](/docs/reference/client/disconnect-reason#clientrequested), but it keeps the link open until the gateway closes it, which is how it knows the goodbye arrived, or until `timeoutSeconds` has passed. [`IsLeaving`](#isleaving) is true until then, and [`LeaveFinished`](#leavefinished) says which it was. Before quitting, wait for it: `yield return client.LeaveAndWait();` then `Application.Quit()`. A goodbye that does not arrive costs nothing but the grace: the server treats the player as disconnected.

With no welcomed connection there is nobody to say goodbye to: it acts like [`Disconnect`](#disconnect) and raises [`LeaveFinished`](#leavefinished) with false at once.

### LeaveAndWait [#leaveandwait]

```csharp
public System.Collections.IEnumerator LeaveAndWait(float timeoutSeconds = DefaultLeaveTimeoutSeconds);
```

[`Leave`](#leave), then wait until the gateway has confirmed the goodbye or `timeoutSeconds` has passed. Run it as a coroutine before quitting: `yield return client.LeaveAndWait(); Application.Quit();`. The client keeps polling its transport in `Update` meanwhile, so the frame loop must keep running.
