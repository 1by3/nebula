The worker's half of the scope lifecycle (`docs/scope-lifecycle.md`): it keeps the idle clock of the scope parts it owns honest, performs the retire sequence for a scope the orchestrator moved to [`ScopeState.Retiring`](/docs/reference/control-plane/scope-state#retiring), and reports a restore finished for a scope in [`ScopeState.Restoring`](/docs/reference/control-plane/scope-state#restoring). It decides nothing — the orchestrator owns the state machine and this only ever acts on the state it reads off the control-plane document.

The retire sequence for one part, in order: the **before-retire window** ([`BeforeRetire`](#beforeretire), the seam NEB-242 exposes as `OnBeforeRetire(container, cancelToken)`), a forced checkpoint of every persistent entity in the part, the store's write barrier, emptying the part, and only then the acknowledgement the orchestrator waits for before it deletes the lease rows.

### BeforeRetireTimeoutSeconds [#beforeretiretimeoutseconds]

```csharp
public const float BeforeRetireTimeoutSeconds = 10f;
```

How long the before-retire window may run before it is cancelled and the retire carries on regardless. Kept below [`ScopeLifecycle.StepTimeoutSeconds`](/docs/reference/control-plane/scope-lifecycle#steptimeoutseconds) so the checkpoint still happens inside the orchestrator's deadline rather than being cut off by it.

### ActivatingTimeoutSeconds [#activatingtimeoutseconds]

```csharp
public const float ActivatingTimeoutSeconds = 10f;
```

How long the restore of a scope's parts waits for the store to answer "has this scope any records?" before it goes ahead without `NebulaLifecycle.OnScopeActivating` having been raised. The safety valve of `docs/lifecycle-hooks.md` D4: a store that never answers must not stop a scope coming back.
