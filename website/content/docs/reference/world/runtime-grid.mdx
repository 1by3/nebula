Maps runtime containers to a planar or three-dimensional grid. Provides a stable 64-bit id per cell, cell bounds in the current floating-origin frame, and neighborhood queries.

Each id packs three signed 21-bit coordinates. Keep this format stable because container leases and persisted entities use these ids to identify cells.

### Planar [#planar]

```csharp
public bool Planar { get; }
```

Cells are columns: the grid has a single layer at y = 0 and [`CellSize`](#cellsize).y is the column's height, centered on absolute y = 0. Surface worlds want this — a chunk that is 64 m wide and 512 m tall is one container nothing ever leaves vertically, so verticality never costs a cell, a lease, or a neighborhood dimension. The packing is unchanged (y is simply always 0), so a planar and a volumetric grid produce the same ids for the same coordinates.

### Frame [#frame]

```csharp
public ScopeFrame Frame { get; }
```

This grid's floating-origin frame: [`WorldOrigin`](/docs/reference/world/world-origin) for the public world, and a frame of its own for every other scope. Every piece of arithmetic below is relative to it, which is what lets two scopes on one worker both sit near Unity's origin (`docs/scope-frames.md`). A hosted grid's frame follows its host's floating origin ([`ScopeFrame.IsFollowing`](/docs/reference/world/scope-frame#isfollowing)): its [`ScopeFrame.OriginOffset`](/docs/reference/world/scope-frame#originoffset) turns the host's own coordinates into simulation space and back, on a worker and on a client while it predicts; a client draws the host where it is ([`PhysicsFrame.ToParent`](/docs/reference/containers/physics-frame#toparent)).

### Hosted [#hosted]

```csharp
public static RuntimeGrid Hosted(ChunkGridDefinition definition, string scopeKey, string gridKey, string hostContainerId, IChunkGridGeometry geometry = null);
```

A grid hosted by a container (`docs/container-tree.md` D22): chunks of `definition`'s size leased as children of `hostContainerId`, laid out in the host's own coordinates, in scope `scopeKey`, with ids derived from `gridKey` and the coordinate. A planar one is a single layer of columns centred on the host's y = 0. The scope key must not be empty (the public world hosts no grids) and the grid key must not be any scope's key. `geometry` replaces the lattice the definition describes with a shape of the game's own (a cube-sphere's faces); its cell size then only sizes the grid's frame. [`NebulaChunkedWorld.ActivateHostedGrid`](/docs/reference/world/nebula-chunked-world#activatehostedgrid) makes one on every worker; build one directly only for a custom allocation workflow.

### TryCoordOf [#trycoordof]

```csharp
public bool TryCoordOf(ulong id, out Vector3Int coord);
```

The chunk an id names in this grid, or false when the id is not this grid's. Always true for the public grid (every 64-bit value unpacks to a coordinate); for a scoped grid it is true for a chunk this process has named or adopted from a lease row ([`Adopt`](#adopt)). The overload that takes a [`PersistedEntityRecord`](/docs/reference/persistence/persisted-entity-record) places a saved entity from its record's part id ([`PersistedEntityRecord.PartId`](/docs/reference/persistence/persisted-entity-record#partid)), adopting the id as it goes, so it works in a process that never named the chunk; it is false for a record of another scope, in no runtime container, or inside a carrier.

### TryFindCoordNear [#tryfindcoordnear]

```csharp
public bool TryFindCoordNear(ulong id, Vector3Int around, int radius, out Vector3Int coord);
```

Find the chunk of this grid named by `id` by trying every coordinate within `radius` cells of `around`: a square in the y = 0 layer for a [`Planar`](#planar) grid, a cube otherwise. Use it for a scoped chunk id this process never named and no record or lease row explains, such as a record saved before [`PersistedEntityRecord.PartId`](/docs/reference/persistence/persisted-entity-record#partid) existed, when the game keeps an approximate position for it. On a match the grid learns the id, as [`Adopt`](#adopt) does.

The search goes outward ring by ring and stops at the first match. It computes one id per coordinate: (2r+1)² for a planar grid and (2r+1)³ for a volumetric one, each a short string hash, so keep the radius to what the hint's error needs. An id the grid already knows is answered from what it knows, wherever the chunk is; the public grid unpacks the id and reports whether the chunk is within the radius. False for a negative radius, or when no coordinate in range matches.

### UseAsRuntimeBounds [#useasruntimebounds]

```csharp
public void UseAsRuntimeBounds();
```

Point [`ContainerRegistry.RuntimeBoundsInFrame`](/docs/reference/containers/container-registry#runtimeboundsinframe) at this grid, so a game that registers runtime containers by [`PackId`](#packid)'d coordinate can use this grid as the bounds hook. Games with their own container shape keep using the hook directly; this is purely opt-in and touches nothing else. Call once at boot, and clear (`ContainerRegistry.RuntimeBoundsInFrame = null`) on shutdown if another hook should take over.

### ShiftOriginTo [#shiftoriginto]

```csharp
public static void ShiftOriginTo(Vector3Int target);
```

Opt-in floating-origin policy for a grid world: shift the origin to `target` (a no-op when it is already there, or when no runtime world is loaded), suspending enabled `CharacterController`s on entities of runtime containers across the shift and syncing physics transforms after. PhysX controllers must be reinserted at the new pose, not sweep over the shift. Call from the game's own update once it has decided where the origin belongs, or use [`KeepOriginNear`](#keeporiginnear) for the usual policy.

### ShiftOrigin [#shiftorigin]

```csharp
public void ShiftOrigin(Vector3Int target);
```

Move **this grid's** origin to `target`. The public world's frame is the process's (the streamer moves the authored cell scenes with it), so that case is [`ShiftOriginTo`](#shiftoriginto) unchanged. A scoped grid owns its frame: only that scope's containers, the entities in them, their state history and interpolation buffers move, and no other scope on this worker notices (`docs/scope-frames.md` D3).

### KeepOriginNear [#keeporiginnear]

```csharp
public void KeepOriginNear(NetworkIdentity entity, int ring = 1);
public void KeepOriginNear(Vector3Int cell, int ring = 1);
```

Keep the floating origin within `ring` cells of `entity` — the usual policy for a client following its local player. Shifts through [`ShiftOriginTo`](#shiftoriginto) when the entity leaves that ring around [`WorldOrigin.Cell`](/docs/reference/world/world-origin#cell), and does nothing otherwise.
