Serves the orchestrator's [`ISharedCacheStore`](/docs/reference/shared-cache/i-shared-cache-store) to workers ([`RemoteSharedCacheClient`](/docs/reference/shared-cache/remote-shared-cache-client)) over the orchestrator's HTTP server, beside [`PersistenceHost`](/docs/reference/persistence/persistence-host):

- `GET /cache/{key}`: the object as `application/octet-stream` with its SHA-256 in `X-Nebula-Checksum`; 404 when there is none
- `PUT /cache/{key}`: the object as the body, with its SHA-256 in `X-Nebula-Checksum`. 201 when it was stored, 200 when the key was already stored. 400 for a bad key, a missing or wrong checksum, or an empty body; 413 over the size limit

Requests carry the mesh token in `X-Nebula-Token` when the mesh has one. Unlike the persistence endpoints, a request is answered on the HTTP server's own thread and never waits for the orchestrator's main thread, so a worker that is filling a cold cache cannot hold up the control plane. To keep it from starving the control plane of the HTTP server's threads instead, at most [`MaxConcurrent`](#maxconcurrent) requests run at once; the rest get 503 and the worker treats that as a miss.
