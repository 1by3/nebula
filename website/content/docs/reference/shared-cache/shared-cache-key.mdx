The rules every part of the shared cache applies to a key and to a stored object: the longest key and object, which characters a key may use, and how an object's checksum is written. A key is chosen by the caller, usually a namespace plus a hash of the inputs that produced the object, such as `terrain.v3.9f2c1a…`.

### DefaultMaxObjectBytes [#defaultmaxobjectbytes]


Largest object a cache accepts by default, in bytes (32 MiB). [`NebulaConfig.SharedCacheMaxObjectBytes`](/docs/reference/core/nebula-config#sharedcachemaxobjectbytes) changes it; set the same value on the orchestrator and on every worker.

### DefaultExpiryDays [#defaultexpirydays]

```csharp
public const int DefaultExpiryDays = 30;
```

Days a key may go unread before the orchestrator removes it, by default.

### TouchIntervalSeconds [#touchintervalseconds]

```csharp
public const int TouchIntervalSeconds = 24 * 60 * 60;
```

Seconds an entry's last-read time may lag behind the real time before a read refreshes it. Reads inside this window do not write to the store, so a busy key costs no database writes.

### TryValidate [#tryvalidate]


True when `key` can be used: 1 to [`MaxKeyLength`](#maxkeylength) characters from `A-Z a-z 0-9 . _ - :`, starting with a letter or digit. Anything else is refused with a reason in `error`.
