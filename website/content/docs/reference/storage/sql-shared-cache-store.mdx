[`ISharedCacheStore`](/docs/reference/shared-cache/i-shared-cache-store) in the orchestrator's database ([`NebulaDatabase`](/docs/reference/storage/nebula-database): SQLite or PostgreSQL), table `shared_cache`. It is separate from `nebula_entity`, so persistence's [`IPersistenceStore.Clear`](/docs/reference/persistence/i-persistence-store#clear) and a world wipe leave it alone. Each call uses its own pooled connection, so reads and writes run in parallel with persistence's writer thread; a write is one `INSERT … ON CONFLICT DO NOTHING`, which makes the table write-once and lets two racing puts both succeed.
