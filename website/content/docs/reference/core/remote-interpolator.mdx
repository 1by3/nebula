Tick-indexed pose buffer for copies of an entity this process does not simulate: ghosts on a worker and remote entities on a client. The consumer decides at which (fractional) tick to sample.

Samples are kept in the space they arrived in: container-local, tagged with the container. A pose inside a moving container (a passenger on a ship) is therefore interpolated relative to the ship, and the sampled local pose is applied under the ship's transform wherever the ship is *now*, so passengers never lag a frame behind the hull. A sample with no container is a world pose (an entity outside every container).

### Sample [#sample]

```csharp
public bool Sample(double renderTick, out Container container, out Vector3 localPosition, out Quaternion localRotation);
public bool Sample(double renderTick, out Vector3 position, out Quaternion rotation);
```

Interpolated pose at `renderTick`, in the space of `container` (the newer sample's container; null means world). Falls back to extrapolating from the newest sample by its velocity (capped) when asked for a time we have not received yet. Apply it with [`NetworkIdentity.SetLocalPose`](/docs/reference/core/network-identity#setlocalpose) so an entity under a moving container lands where the container is this frame.
