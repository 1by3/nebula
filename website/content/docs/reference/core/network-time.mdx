Provides the shared simulation tick. Each worker calculates its tick from the wall clock and a fixed origin, so workers agree without a coordinating process. Use tick numbers rather than wall-clock timestamps in gameplay simulation.

The tick rate is [`DefaultTickRate`](#defaulttickrate) (60 Hz) unless the game sets `NebulaConfig.TickRate` (docs/tick-rate.md). Every process of a mesh runs at the same rate: workers, the orchestrator and the gateway read it from the configuration (or `-nebula-tick-rate`, or the `NEBULA_TICK_RATE` environment variable), and a client takes it from the gateway's [`WelcomeMsg.TickRate`](/docs/reference/protocol/welcome-msg#tickrate). Code that means a duration should hold it in seconds and convert with [`SecondsToTicks`](#secondstoticks), so it keeps its meaning at any rate; a tick count is right only for what is counted in steps (a number of inputs, a snapshot buffer depth).

## Methods

### Configure [#configure]

```csharp
public static int Configure(int ticksPerSecond);
```

Set the tick rate of this process: [`ClampRate`](#clamprate) of `ticksPerSecond`. Workers, gateways and orchestrators call it at start-up from the configuration; a client calls it again with the rate its gateway welcomed it with. Returns the rate in use.


A duration in ticks at the current rate, rounded up (0 for 0 or less): for a margin that must cover at least `seconds`. A thousandth of a tick of slack absorbs a float's rounding (32/60 s stored as a float is 32.000002 ticks at 60 Hz, which is 32, not 33).

A count of ticks tuned at [`DefaultTickRate`](#defaulttickrate) (an interval or a divisor), rescaled so it lasts as long at the current rate: rounded, at least 1. 0 or less is returned unchanged (it usually means none, or off).
