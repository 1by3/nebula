```csharp
[RequireComponent(typeof(NetworkIdentity))]
public abstract class NetworkBehaviour : MonoBehaviour
```

Base class for replicated gameplay components. Use [`IsServer`](#isserver), [`IsClient`](#isclient), and [`IsOwner`](#isowner) to inspect the current role. Use [`HasAuthority`](#hasauthority) to check whether this worker controls the entity, and [`IsGhost`](#isghost) to check whether it holds a non-authoritative copy. Override the lifecycle methods to respond to spawn, despawn, and authority changes.

### SyncAudience [#syncaudience]

```csharp
public virtual SyncAudience SyncAudience { get; }
```

Which clients receive this behavior's sync state ([`WriteSyncState`](#writesyncstate)). The default, `SyncAudience.Everyone`, costs nothing. A worker that holds a ghost of the entity receives the state whatever the audience; only clients are filtered. Override it with a constant: Nebula reads it once, when the entity is spawned or instantiated, so it is configuration and not state that can change at run time. An entity's root [`NetworkTransform`](/docs/reference/core/network-transform) always replicates to everyone.

[`NetworkVariable<T>`](/docs/reference/core/network-variable)s are not covered: an entity's variables go to every client that holds it. Keep state a client must not see in sync state with a restricted audience.

### SyncAudienceRefreshTicks [#syncaudiencerefreshticks]

```csharp
public virtual uint SyncAudienceRefreshTicks { get; }
```

For the `Custom` audience only: how often, in ticks, the authority evaluates the audience again without being asked. The default is 30, half a second at the 60 Hz tick rate. Return 0 to evaluate only when the entity gains authority and after [`MarkSyncAudienceDirty`](#marksyncaudiencedirty). That suits a rule that changes only on events, such as a player opening or closing a container.

### WriteHandoverState [#writehandoverstate]

```csharp
public virtual void WriteHandoverState(NetworkWriter writer);
```

Called on the outgoing worker while building an authority transfer, before [`OnLostAuthority`](#onlostauthority). Write any state the next owner needs that is not already replicated (angular velocity, timers, RNG state...). Travels only with the handover, never in the per-tick stream. Must be mirrored exactly by [`ReadHandoverState`](#readhandoverstate).

### ReadHandoverState [#readhandoverstate]

```csharp
public virtual void ReadHandoverState(NetworkReader reader);
```

Called on the incoming worker after the entity's pose, velocity and NetworkVariables have been applied and before [`OnGainedAuthority`](#ongainedauthority). Read exactly what [`WriteHandoverState`](#writehandoverstate) wrote.

### WritePersistentState [#writepersistentstate]

```csharp
public virtual void WritePersistentState(NetworkWriter writer);
```

Called while the worker builds this entity's persistence record. Write what the entity needs to come back as it was and that no [`PersistAttribute`](/docs/reference/persistence/persist-attribute) variable already covers. Must be mirrored exactly by [`ReadPersistentState`](#readpersistentstate). Writing nothing (the default) costs nothing: an entry is only added when bytes were written.

Unlike [`WriteHandoverState`](#writehandoverstate), this is read back by a later run and possibly a later build, so treat it as a save format and version it yourself if you expect it to change.

### ReadPersistentState [#readpersistentstate]

```csharp
public virtual void ReadPersistentState(NetworkReader reader);
```

Called on a restored entity before it is spawned, with exactly what [`WritePersistentState`](#writepersistentstate) wrote. The reader is bounded to this behaviour's own chunk, so reading too much fails here (and is logged) instead of corrupting the rest of the record.

### IsInSyncAudience [#isinsyncaudience]

```csharp
protected virtual bool IsInSyncAudience(ulong clientId, NetworkIdentity pawn);
```

For the `Custom` audience only, on the authoritative worker: whether the client with session ID `clientId` should receive this behavior's sync state. `pawn` is that client's player entity as this worker holds it (simulated here or a ghost), so a rule can measure the distance to it. Nebula asks about every client whose pawn this worker holds: when the entity gains authority, every [`SyncAudienceRefreshTicks`](#syncaudiencerefreshticks) ticks, and at the next tick after [`MarkSyncAudienceDirty`](#marksyncaudiencedirty). A client whose pawn this worker does not hold is not asked, and is not in the audience. Keep it cheap and free of side effects. By default it returns false for every client.

| Parameter | Description |
| --- | --- |
| `clientId` | The client's session ID. It stays the same when the client reconnects ([`NetworkIdentity.OwnerClientId`](/docs/reference/core/network-identity#ownerclientid)). |
| `pawn` | That client's player entity on this worker. |

### MarkSyncAudienceDirty [#marksyncaudiencedirty]

```csharp
protected void MarkSyncAudienceDirty();
```

For the `Custom` audience only, on the authority: the answer of [`IsInSyncAudience`](#isinsyncaudience) may have changed, so evaluate it at the next tick instead of waiting for the refresh. Calling it often is cheap: the audience is evaluated at most once per tick.

### OnSyncStateCleared [#onsyncstatecleared]

```csharp
public virtual void OnSyncStateCleared();
```

Client side: this client has just left the behavior's audience. For example, it no longer owns the entity, or a Custom rule stopped choosing it. None of the behavior's sync state arrives until the client joins again, and then a keyframe arrives through [`ReadSyncState`](#readsyncstate). Drop what you hold of that state and clear any UI that shows it. Not called when the entity itself leaves the client (see [`OnNetworkDespawn`](#onnetworkdespawn)).

### WriteSyncState [#writesyncstate]

```csharp
public virtual void WriteSyncState(NetworkWriter writer, bool full);
```

Authority only. Write the state to replicate. When `full` is true write everything (a keyframe: this is what a late joiner or a fresh ghost will start from); otherwise only what changed since the last write is needed, though writing everything is always correct.

### RemoteTick [#remotetick]

### AuthorityRpcWithReply [#authorityrpcwithreply]

```csharp
protected ulong AuthorityRpcWithReply(Action method, Action<AuthorityCallResult> onDone, float timeoutSeconds = DefaultAuthorityCallTimeoutSeconds);
protected ulong AuthorityRpcWithReply<T1>(Action<T1> method, T1 a1, Action<AuthorityCallResult> onDone, float timeoutSeconds = DefaultAuthorityCallTimeoutSeconds);
protected ulong AuthorityRpcWithReply<T1, T2>(Action<T1, T2> method, T1 a1, T2 a2, Action<AuthorityCallResult> onDone, float timeoutSeconds = DefaultAuthorityCallTimeoutSeconds);
protected ulong AuthorityRpcWithReply<T1, T2, T3>(Action<T1, T2, T3> method, T1 a1, T2 a2, T3 a3, Action<AuthorityCallResult> onDone, float timeoutSeconds = DefaultAuthorityCallTimeoutSeconds);
protected ulong AuthorityRpcWithReply<T1, T2, T3, T4>(Action<T1, T2, T3, T4> method, T1 a1, T2 a2, T3 a3, T4 a4, Action<AuthorityCallResult> onDone, float timeoutSeconds = DefaultAuthorityCallTimeoutSeconds);
```

As [`AuthorityRpc`](#authorityrpc), and also tells you what became of the call. `onDone` runs exactly once, on the worker's main thread: with [`AuthorityCallOutcome.Accepted`](/docs/reference/worker/authority-call-outcome#accepted) once the worker with authority has run the method, with the reason when a worker on the path rejected it, or with [`AuthorityCallOutcome.TimedOut`](/docs/reference/worker/authority-call-outcome#timedout) when no answer arrived within `timeoutSeconds`. Returns the call id, or 0 when the call was applied locally or refused before it was sent. The delivery contract is described in the RPC guide.
