Where RPCs and state changes go once a behaviour has produced them. Implemented by the worker and the client.

## Methods

### SendClientRpc [#sendclientrpc]

```csharp
void SendClientRpc(NetworkIdentity identity, byte behaviourIndex, uint methodHash, ArraySegment<byte> args, ulong targetClientId, float radius);
void SendClientRpc(NetworkIdentity identity, byte behaviourIndex, uint methodHash, ArraySegment<byte> args, ulong targetClientId, float radius, Delivery delivery);
```

As [`SendClientRpc`](#sendclientrpc), on the given delivery class ([`ClientRpcAttribute.Delivery`](/docs/reference/core/client-rpc-attribute#delivery)). The default forwards to the reliable overload, so a sink written before delivery classes existed keeps compiling and sends everything reliable.

### SendAuthorityRpc [#sendauthorityrpc]

```csharp
void SendAuthorityRpc(NetworkIdentity identity, byte behaviourIndex, uint methodHash, ArraySegment<byte> args);
ulong SendAuthorityRpc(NetworkIdentity identity, byte behaviourIndex, uint methodHash, ArraySegment<byte> args, Action<AuthorityCallResult> onDone, float timeoutSeconds);
```

As [`SendAuthorityRpc`](#sendauthorityrpc), with the outcome reported to `onDone` exactly once: the reply from the worker that decided the call, or [`AuthorityCallOutcome.TimedOut`](/docs/reference/worker/authority-call-outcome#timedout) after `timeoutSeconds`. Returns the call id, or 0 when nothing was sent (the callback still runs, with the reason).
