Who sent a [`client request`](/docs/reference/core/client-request-rpc-attribute), handed to the handler as its first parameter. The sender fields are stamped by the gateway from the connection and the session: a client cannot choose or change them. The arguments that follow the context are the client's, and are not to be trusted.

The sender's verified identity across sessions ([`PlayerIdentity`](/docs/reference/gateway/player-identity)): the account or provider subject of a verified sign-in token, or an anonymous identity the mesh issued. Key anything that must outlive a session on this, not on [`ClientId`](#clientid).

The claims of the sender's verified token that the mesh forwards ([`NebulaConfig.ForwardedClaims`](/docs/reference/core/nebula-config#forwardedclaims)); empty for an anonymous player. As of the sign-in: a role granted since is not here until the player signs in again.

### SenderPosition [#senderposition]

```csharp
public Vector3 SenderPosition { get; }
```

Where the gateway last saw the sender's pawn, in the scope's own absolute space: the space of [`NetworkIdentity.ScopePositionPrecise`](/docs/reference/core/network-identity#scopepositionprecise), so a distance check against [`Entity`](#entity) needs no pawn on this worker. One interest update old at worst, and the sender can move meanwhile: allow for that in a range check.

### ReplyCode [#replycode]

```csharp
public ushort ReplyCode { get; set; }
```

Your own verdict for the client, if it asked for a reply: set it in the handler ("done", "too far", "not yours"). Sent with [`ClientRequestOutcome.Accepted`](/docs/reference/protocol/client-request-outcome#accepted) in [`ClientRequestResult.Code`](/docs/reference/protocol/client-request-result#code). 0 by default. Ignored when no reply was asked for.
