An [`ITransport`](/docs/reference/transport/i-transport) that adds the latency, jitter and packet loss of a [`NetworkSimulation`](/docs/reference/transport/network-simulation) to every link of another transport, in both directions, without touching the remote side. Wrap a client's transport to see how the game behaves on a slow link while the server runs on the same machine. It does not depend on LiteNetLib's debug-only simulation, so it works in the Editor and in development builds alike.

Outgoing packets are held for half the configured latency before the inner transport sends them; incoming packets are held for the other half before [`Poll`](#poll) delivers them. A request and its reply therefore take the configured latency longer, plus the link's own time. [`RoundTripMs`](#roundtripms) adds the configured latency to the inner link's measurement, because the inner transport's own keep-alive packets never pass through the simulation. Connection and disconnection events are not delayed, so a link opens and closes at its real time. Held packets are released from [`Poll`](#poll) and [`Flush`](#flush), so the effective resolution is how often your game calls them: once per tick.
