Network conditions to simulate on one link, for testing prediction and lag compensation on one machine. [`LatencyMs`](#latencyms) is the added **round trip**: half of it delays each packet the link sends and the other half delays each packet it receives. All values are clamped to a sensible range on use.

## Properties

### LatencyMs [#latencyms]

```csharp
public float LatencyMs { get; }
```

Added round-trip time in milliseconds: `LatencyMs / 2` in each direction. 0 adds none.

### JitterMs [#jitterms]

```csharp
public float JitterMs { get; }
```

Jitter in milliseconds: each packet's delay in each direction varies by a random amount between `-JitterMs / 2` and `+JitterMs / 2` around its half of [`LatencyMs`](#latencyms), never below zero. A packet sent after another can therefore arrive first; a [`Delivery.Sequenced`](/docs/reference/transport/delivery#sequenced) packet that is overtaken is dropped, as a real sequenced link does, and reliable packets stay in order.

### LossPercent [#losspercent]

```csharp
public float LossPercent { get; }
```

Percent of packets lost in each direction, 0 to 100. A lost [`Delivery.Sequenced`](/docs/reference/transport/delivery#sequenced) packet never arrives. A lost reliable packet arrives one extra round trip late, as a retransmission would, and holds up the reliable packets behind it.
