Worker -\> gateway: this gateway no longer speaks for the session, because the player connected again through another gateway ([`NebulaConfig.SingleSessionPerPlayer`](/docs/reference/core/nebula-config#singlesessionperplayer)). The gateway lets its client go with a [`SessionReplacedMsg`](/docs/reference/protocol/session-replaced-msg) and does not despawn the pawn, which the new connection has taken over. Fenced by [`Generation`](#generation) the same way [`SpawnPlayerMsg`](/docs/reference/protocol/spawn-player-msg) is: a gateway that has since claimed the session with a newer generation ignores it.
