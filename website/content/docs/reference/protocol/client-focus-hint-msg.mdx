Client -\> gateway: where the player is looking, as a hint for interest (a sniper scope, an RTS camera). The gateway validates it ([`FocusHintFilter`](/docs/reference/interest/focus-hint-filter)) before any policy sees it: a hint is an input, never authority, so it cannot be used to see the whole map.

## Fields

### X, Y, Z [#x-y-z]

```csharp
public double X, Y, Z;
```

The hinted point in **absolute** world coordinates, in double — the same space region keys, container boxes and the gateway's own positions are in, and the only space both ends agree on. A client sends its floating-origin frame position plus its origin (`NebulaClient` does the sum), so a shift under the camera changes the frame position and the origin together and the point the gateway sees does not move. Floats would lose meters out at the edge of an unbounded world, which is exactly where a strategy camera is pointed, so this is three doubles and not a `Vector3`.

### Generation [#generation]

```csharp
public byte Generation;
```

Bumped by the client every time it clears its hint. Hints travel [`Delivery.Sequenced`](/docs/reference/transport/delivery#sequenced) and the clear travels reliably, so a hint already in flight can arrive after the clear; without a generation it would quietly re-establish the focus the game just gave up.

### Clear [#clear]

```csharp
public bool Clear;
```

The client withdraws its hint: interest returns to the pawn. The position is unused.
