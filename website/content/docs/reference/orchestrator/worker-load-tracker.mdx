How busy each worker is, as a fraction of its tick budget: `WorkerInfo.TickMs / tickPeriodMs`, sampled from every heartbeat and kept for a short window ([`NebulaConfig.ScaleWindowSeconds`](/docs/reference/core/nebula-config#scalewindowseconds)). The 90th percentile of that window is the scaling signal: a GC spike does not launch a machine, a sustained 80 % does.

The tracker is a plain object with an injected clock, so the scaler can be exercised over synthetic histories without a mesh or Unity time. Samples are kept in a per-worker ring of structs and the percentile is taken from a reused scratch buffer, so a pass allocates nothing once the mesh is warm.

### MinSamples [#minsamples]

How many heartbeats a worker must have inside the window before its utilization means anything. Below this it reads as 0 % busy simply because nothing has been reported yet, which is how a freshly launched worker used to become the cheapest one to retire ([`WorkerScaler.IsWarm`](/docs/reference/orchestrator/worker-scaler#iswarm)).

### Attribute [#attribute]

```csharp
public static void Attribute(IReadOnlyDictionary<string, float> workerUtilization, IReadOnlyList<LeaseInfo> leases, IReadOnlyDictionary<string, ContainerLoad> occupancy, in CostWeights weights, Dictionary<string, float> result);
```

Spread each worker's p90 utilization over the containers it leases, in proportion to what [`CostWeights`](/docs/reference/orchestrator/cost-weights) says their occupants cost. A container nobody reported gets [`CostWeights.Base`](/docs/reference/orchestrator/cost-weights#base), so an empty container still carries its share of the worker's floor. A worker holding no container contributes nothing; its load shows up in the mesh's mean only.

This is a proxy: a container full of static props costs less than one full of NPCs chasing paths. The hint's cost multiplier (phase 3) is the manual correction.

| Parameter | Description |
| --- | --- |
| `result` | Cleared and filled with container id -\> attributed utilization. |
