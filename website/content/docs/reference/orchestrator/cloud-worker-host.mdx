An [`IWorkerHost`](/docs/reference/orchestrator/i-worker-host) for managed hosting: instead of calling a cloud provider, the orchestrator asks a deployment-scoped resource API for a worker (`POST /d/workers`), polls the list for its state and private address, and deletes, parks and unparks through the same API. The service behind it holds the provider credentials and turns each request into a machine; the orchestrator's machine never sees an account-wide credential. Nebula's own assignment, drain, replacement and scale-to-zero logic is untouched: this host only changes where a worker comes from.

The API is documented by the hosting platform; the shapes this class relies on are: a worker resource `{workerId, resourceId, index, state, privateAddress, size, reason, parkedUntil}` with states `launching | running | parked | exiting | exited | failed`, wrapped as `{"worker": …}` on single answers and `{"workers": […]}` on the list, and an error envelope `{"error": {"code", "message"}}`. A create answers 402 when the deployment reached its spend limit and 409 when it is at its worker ceiling.

All HTTP work runs on the thread pool; results are applied in [`Tick`](#tick) on the main thread.
