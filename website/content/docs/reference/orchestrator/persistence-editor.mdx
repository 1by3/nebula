Reads and rewrites persisted records for the dashboard's Persistence tab (`/persistence`).

The standalone orchestrator reads field schemas exported from game prefabs and scene entities at build time. Fields use the same names as [`PersistentStateCodec`](/docs/reference/persistence/persistent-state-codec) (`"<BehaviourTypeName>.<FieldName>"`). Built-in types and exported enumerations have typed controls. Custom types, unknown fields, and a behavior's own `#state` chunk are shown and edited as hex. The legacy Unity host discovers these schemas from assets.

Loads are asynchronous (the store answers from [`IPersistenceStore.Tick`](/docs/reference/persistence/i-persistence-store#tick)), so the editor keeps a snapshot of every record and refreshes it at most every [`SnapshotMaxAgeSeconds`](#snapshotmaxageseconds) seconds while the page polls. Every method here must run on the main thread, from the orchestrator's command pump.

**Caveat.** An edit lands in the store, not in a running worker. While an entity is alive and authoritative somewhere, its next checkpoint overwrites whatever you saved here. Edit records of entities that are not alive (the mesh is stopped, or the entity was deleted), or fields the entity never writes back.

### Refresh [#refresh]

```csharp
public void Refresh(bool force);
```

Reload the snapshot when it is older than [`SnapshotMaxAgeSeconds`](#snapshotmaxageseconds) (or always, when `force`). Both stores answer a load from memory through their callback queue, so one [`IPersistenceStore.Tick`](/docs/reference/persistence/i-persistence-store#tick) hands the result back inside this call whenever the store is ready.
