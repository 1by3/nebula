The interest settings, resolved from [`NebulaConfig`](/docs/reference/core/nebula-config) and already clamped into a set of values that work together (see [`Validate`](#validate)). Everything downstream — grid, per-client evaluation, subscription margins, worker publishing — reads this and nothing else, so the standalone gateway and the Unity worker cannot drift apart over what "near" means.

## Methods

### TiersFor [#tiersfor]

```csharp

```

The distance tiers an entity of `priority` is sent by: its own when the config overrides them ([`HighTiers`](#hightiers), [`LowTiers`](#lowtiers), [`BackgroundTiers`](#backgroundtiers)), otherwise the global ones ([`NearRadius`](#nearradius), [`FarRadius`](#farradius), [`MidDivisor`](#middivisor), [`FarDivisor`](#fardivisor)) shifted as [`RelevancePriority`](/docs/reference/interest/relevance-priority) describes. ### NearCells [#nearcells]

```csharp
public int NearCells(float cellSize);
```

The cells of content that must exist before interest needs them. Content streaming, the runtime allocator ring and the container window a client is told about all derive from this, so a client can never be spawned an entity standing on geometry it does not have.

### ChunkRing [#chunkring]

```csharp
public int ChunkRing(float cellSize, int margin);
```

The Chebyshev ring of chunks a worker keeps leased around every pawn: [`NearCells`](#nearcells) plus `margin` extra cells (never fewer than [`NearCells`](#nearcells), which is the least that has every chunk interest can reach). `NebulaConfig.ChunkedWorldServerRingMargin` is the margin; 1 builds content one whole chunk before interest needs it.

### ChunkLoadLeadSeconds [#chunkloadleadseconds]

```csharp
public float ChunkLoadLeadSeconds(float cellSize, int margin);
```

Seconds between a pawn at [`MaxFocusSpeed`](#maxfocusspeed) walking into a chunk and the first chunk its new ring adds being needed by interest: the ring reaches `ring × cell` metres from the chunk edge it just crossed, and interest reaches the exit radius plus the overshoot. Zero margin leaves only the slack [`NearCells`](#nearcells) rounds up by (up to one cell, none when the radius is a whole number of cells); each further margin cell adds a cell of travel. Infinity when nothing moves or there is no cell size.

### MaxContainerRows [#maxcontainerrows]

```csharp
public int MaxContainerRows(float cellSize);
```

Most container rows one client may be told about in one evaluation: the ceiling on the `NearCells` windows the gateway opens around a client's foci. Derived rather than configured, because every part of it is already a setting: a window is `2 × NearCells + 1` cells on a side, a planar world stacks nothing above it, and a client may hold [`MaxFoci`](#maxfoci) foci. It is a safety net and not a budget to aim at — the rows entities in the set stand in are collected before it applies, so reaching it can only ever withhold empty terrain a camera is looking at.

Clamped to \[64, 4096\] so a tiny world still gets a usable window and an enormous `InterestRadius` cannot turn one evaluation into a lease-table broadcast.

### Validate [#validate]

```csharp
public InterestSettings Validate(List<ConfigIssue> issues, float worldCellSize = 0f, float ghostBandMargin = 0f);
```

Check the setting relationships and return the values that will actually be used. Anything that can be repaired is repaired and reported as a [`ConfigSeverity.Warning`](/docs/reference/interest/config-severity#warning); only a non-positive size is an [`ConfigSeverity.Error`](/docs/reference/interest/config-severity#error), because no clamp of it would be what the game asked for. `worldCellSize` is the world definition's cell size (0 = none) and `ghostBandMargin` the meshing band, both of which constrain the region size.
