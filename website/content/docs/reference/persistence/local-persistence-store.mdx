In-process [`IPersistenceStore`](/docs/reference/persistence/i-persistence-store) with the exact write rules of the persistence module (epoch check, version bump), optionally backed by a file so a single-process run survives a restart. This is what `-nebula-persistence-mode local` uses (and what the tests use); a mesh wants the orchestrator's database instead ([`RemotePersistenceStore`](/docs/reference/persistence/remote-persistence-store) on every worker), because every worker needs to see the same records.

Writes land in memory at once. Ordinary writes are debounced by [`WriteIntervalSeconds`](#writeintervalseconds); durability barriers are grouped for [`WriteBarrierIntervalSeconds`](#writebarrierintervalseconds) and share a background rewrite from an immutable snapshot. Callbacks are delivered from [`Tick`](#tick) after that rewrite has completed, so game code sees the same main-thread ordering whichever store it runs on.
