Whether the answer a store is delivering right now is a stand-in for one the backend could not give.

Every read and every [`IPersistenceStore.WhenWritten`](/docs/reference/persistence/i-persistence-store#whenwritten) is answered exactly once, even when the backend fails for good (a store gives up on a job after a few attempts). A read it could not answer gets the empty result — a null record, an empty list, an empty entry per container, a count of 0 — and a barrier is released, after the store has logged the error. While such a callback runs, [`Failed`](#failed) is true, so a caller that must not mistake "unreadable" for "nothing saved" can tell them apart. The orchestrator's [`PersistenceHost`](/docs/reference/persistence/persistence-host) answers those requests with HTTP 503, and the worker retries.
