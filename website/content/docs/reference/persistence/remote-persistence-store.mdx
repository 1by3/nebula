[`IPersistenceStore`](/docs/reference/persistence/i-persistence-store) for a worker: every save and load goes to the orchestrator, which owns the real store ([`PersistenceHost`](/docs/reference/persistence/persistence-host) over the dashboard address, the same one the control plane uses).

Saves are coalesced per key and posted in batches from a sender thread a fraction of a second after they are issued; a batch the orchestrator cannot take is kept and retried, so nothing is lost while it is away. Loads run one request each on the thread pool, retried until they succeed, and their answers are handed back from [`Tick`](#tick) on the main thread like every other store. [`IsConnected`](#isconnected) and [`KnownCount`](#knowncount) come from a status probe every few seconds.
