Long-term storage for entities that opted into persistence ([`PersistentEntity`](/docs/reference/persistence/persistent-entity)). One store per process; the worker's [`NebulaPersistence`](/docs/reference/persistence/nebula-persistence) writes checkpoints through it and reads containers back when it gains a lease. In a mesh the orchestrator owns the store (SQLite or PostgreSQL through the standalone services' `SqlPersistenceStore`, next to the control plane in the same database) and workers reach it through [`RemotePersistenceStore`](/docs/reference/persistence/remote-persistence-store); [`LocalPersistenceStore`](/docs/reference/persistence/local-persistence-store) serves single-process runs and tests.

The contract is request/response on purpose (no subscriptions), so a relational backend fits behind it. Every callback lands on the main thread from [`Tick`](#tick). Writes are fire-and-forget ([`WhenWritten`](#whenwritten) is the barrier for the few callers that must wait): a save is accepted by the backend when its epoch is not older than the stored one, otherwise dropped, and the caller never waits. The store is never on the per-tick path: if it is unreachable the mesh keeps simulating and saves are retried on the next checkpoint.

### WhenWritten [#whenwritten]

```csharp
void WhenWritten(Action onWritten);
```

Calls `onWritten` on the main thread once every save and delete issued before this call has reached the backend. It says the writes were delivered, not that each was kept (a stale epoch is still dropped): follow it with one [`Load`](#load) when the outcome matters, instead of polling.

### LoadWhere [#loadwhere]

```csharp
void LoadWhere(Func<PersistedEntityRecord, bool> predicate, Action<IReadOnlyList<PersistedEntityRecord>> onLoaded);
```

Every record that matches `predicate`. For tools and game directors, not for the per-lease restore path. This is the **offline read**: the records of a scope nothing is simulating are ordinary records and can be read, and written, without activating it (`docs/lifecycle-hooks.md` §5).

### CountRecords [#countrecords]

```csharp
void CountRecords(string scopeKey, string containerId, Action<int> onCounted);
```

How many records the store holds for a scope, **without reading them**. `scopeKey` is matched exactly ([`EntityLocation.PublicScope`](/docs/reference/containers/entity-location#publicscope), the empty key, is the public world) and `containerId` narrows the count to one container when it is non-empty; records inside a carrier are counted like any other. Cheap on purpose — a `COUNT` on the backend, never a list — so that "is there anything saved here?" can be asked on the path that brings a scope to life. The answer lands on the main thread like every other read. Behind `NebulaLifecycle.OnScopeActivating`'s `hasRecords`.
