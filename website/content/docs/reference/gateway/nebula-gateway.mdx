Accepts client connections and maintains a connection to every worker. It forwards each client's inputs to the worker currently owns that client's entity, and fans the workers' replication streams out to the clients, de-duplicating by authority epoch so a handover is invisible to the client. Nothing here is authoritative: if the gateway dies, clients reconnect and the workers re-announce their entities.

Any number of gateways can serve one mesh. Each has a persistent id and an incarnation that changes on every start; sessions get mesh-wide ids ([`SessionIds`](/docs/reference/gateway/session-ids)) and a signed session token ([`SessionTokens`](/docs/reference/gateway/session-tokens)) with which a client can reconnect through any gateway and keep its pawn. A gateway asked to drain refuses new clients and tells the ones it has to reconnect elsewhere. It reports its load on every control-plane heartbeat ([`GatewayStats`](/docs/reference/control-plane/gateway-stats)) for whoever sizes the fleet.

The CLI runs this routing loop in a standalone .NET executable using exported container geometry. The Unity component remains available for compatibility and in-process tests.

### InterestPolicy [#interestpolicy]

```csharp
public IInterestPolicy InterestPolicy { get; set; }
```

The game's say in what each client hears about. Defaults to [`DefaultInterestPolicy`](/docs/reference/interest/default-interest-policy): one focus at the pawn plus the client's validated hint. Compose several with [`InterestPolicies.Combine`](/docs/reference/interest/interest-policies#combine). If the policy also implements [`IFocusHintPolicy`](/docs/reference/interest/i-focus-hint-policy) it gets the say over focus hints too.

Install it before the gateway's first tick — a policy is a security filter, and one installed while clients are already connected has not been asked about what they can already see. Assigning it is the next best thing, and it fails closed: every client's current set is re-authorized against the new policy **synchronously, inside this assignment** ([`RevalidateAllInterest`](#revalidateallinterest)), so nothing the new policy refuses is relayed to anybody afterwards. What the new policy newly allows arrives at the clients' next evaluations, which are still spread over the following ticks.

## Events

### ClientJoined [#clientjoined]

```csharp
public event Action<GatewayClientInfo> ClientJoined;
```

An authenticated client has been welcomed: it has a session id and an identity, and its interest is about to be evaluated for the first time. This is where a server extension gives it its tags and its focus mode, because both are read by the very first evaluation.

Raised on the gateway loop, synchronously, and the gateway is mid-welcome: a handler may call the `SetClient…`/`MarkInterestDirty` methods and read the gateway's own state, but it must not block, and it must not throw (an exception is caught and logged, never passed to the client).

### ClientLeft [#clientleft]

```csharp
public event Action<GatewayClientInfo> ClientLeft;
```

A welcomed client is gone from this gateway: it disconnected, was rejected, or its session was taken over somewhere else (in which case another gateway raises its own [`ClientJoined`](#clientjoined)). Raised on the gateway loop under the same rules as [`ClientJoined`](#clientjoined); by the time it runs the client's interest state has already been let go, so its id no longer resolves.

### SetClientFocusMode [#setclientfocusmode]

```csharp
public void SetClientFocusMode(ulong clientId, FocusMode mode);
```

How far this client's own focus hint may move its interest. The default is [`FocusMode.PawnClamped`](/docs/reference/interest/focus-mode#pawnclamped), so a hint is worth at most [`InterestSettings.HintMaxDistance`](/docs/reference/interest/interest-settings#hintmaxdistance) of the pawn and a client with no pawn has no hint at all; [`FocusMode.Free`](/docs/reference/interest/focus-mode#free) is what gives a strategy camera or a spectator the run of the world. Only the server may set it — the client cannot ask for it, and cannot tell that it has it except by what it is sent.

Instance isolation is unaffected in every mode: a free focus is a wider view of the world the client is already in, never a way into another one.

Changing the mode drops the hint the gateway is holding, because a hint accepted under one mode is not an input the next one ever validated; the client's next hint (within 1/[`InterestSettings.HintMaxHz`](/docs/reference/interest/interest-settings#hintmaxhz) s) is judged afresh.

### MarkInterestDirty [#markinterestdirty]

```csharp
public void MarkInterestDirty(ulong clientId);
```

Put this client at the front of the evaluation queue: a **reveal**, and additive work generally (a party joined, a unit was given to the player, a fog cell was uncovered). The gateway calls it itself when the pawn, instance, carrier, focus mode or focus region changed.

The timing is honest about what it is: dirty clients jump the routine rotation but are still bounded per tick ([`InterestSchedule.MinDirtyPerTick`](/docs/reference/interest/interest-schedule#mindirtypertick), [`InterestSchedule.DirtyBurst`](/docs/reference/interest/interest-schedule#dirtyburst)), so on a busy gateway a client may wait a few ticks for its turn. That is the right trade for showing something *more*, and the wrong one for taking something away: for a change that **tightens** what may be seen call [`RevalidateInterest`](#revalidateinterest), which revokes before this call would even have run.

### MarkAllInterestDirty [#markallinterestdirty]

```csharp
public void MarkAllInterestDirty();
```

The same for every client: a world-wide reveal. The evaluations are spread over the following ticks rather than all run on the next one — see [`InterestSchedule`](/docs/reference/interest/interest-schedule) — so this is cheap to call on a live gateway, and for the same reason it is **not** how a revocation is applied. Use [`RevalidateAllInterest`](#revalidateallinterest) when a sweep can take visibility away.

### RevalidateInterest [#revalidateinterest]

```csharp
public void RevalidateInterest(ulong clientId);
```

Re-authorize everything this client can already see, **now**, and despawn whatever [`IInterestPolicy.Authorize`](/docs/reference/interest/i-interest-policy#authorize) no longer allows before any further traffic about it is relayed. This is the immediate half of [`MarkInterestDirty`](#markinterestdirty) and the call to make whenever a change can take visibility away: a team or alliance change, a stealth roll, fog closing over a region, an access rule revoked.

It costs one authorization per entity the client already holds — no grid query, no candidate scan — and allocates nothing. It never *adds* anything: the client is also marked dirty, so what the same change reveals arrives at its next evaluation, within an eval interval.

Safe to call from a policy callback: a nested call falls back to marking the client dirty rather than re-entering the pass.

### RevalidateAllInterest [#revalidateallinterest]

```csharp
public void RevalidateAllInterest();
```

[`RevalidateInterest`](#revalidateinterest) for every client: a world-wide tightening (a new policy, a war declared, a fog sweep that can close as well as open). Every unauthorized replica on this gateway is gone by the time the call returns.

The cost is one authorization per replica the gateway is currently serving — about what one round of evaluation costs, concentrated into this call instead of spread over an eval interval. That is affordable for the events this is for, and it is the reason the routine rotation is still staggered: this is not a per-tick path, and nothing calls it for ordinary movement or camera updates.
