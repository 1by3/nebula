The physics frames this process holds, one per container with [`Container.OwnPhysicsFrame`](/docs/reference/containers/container#ownphysicsframe) (`docs/container-tree.md` §3): scene lifetime and pooling, interior colliders, frame state, conversion between spaces, the crossing policy, and — on a client — composing the frames into one rendered world.

## Fields

### PoolSize [#poolsize]

```csharp
public static int PoolSize = 8;
```

How many emptied frame scenes are kept for reuse, so a carrier spawning and despawning does not create and unload a scene each time (D13).

### OriginShiftThreshold [#originshiftthreshold]

```csharp
public static float OriginShiftThreshold = 2048f;
```

How far, in metres, the entities a worker simulates in a frame may drift from the frame's origin before [`AutoShift`](#autoshift) moves the origin to them. Physics keeps millimetre precision well past this.

### OriginShiftStep [#originshiftstep]

```csharp

```

The grid a moved origin snaps to, in metres, so two workers that shift for the same crowd agree.

### Convert [#convert]

```csharp
public static Vector3 Convert(Vector3 point, Container from, Container to);
public static Quaternion Convert(Quaternion rotation, Container from, Container to);
```

A point in space `from` expressed in space `to`. A space is a framed container (its frame's local coordinates) or null (the scope's own space). Walks up from `from` to the space both share and down into `to` through each frame owner's transform, so it is exact at this instant in simulation space — which is where a worker is, always.

### ConvertVelocity [#convertvelocity]

```csharp

```

A velocity of a body at `point` (in space `from`) expressed in space `to`: rotated, plus the motion of every frame left (its velocity and ω × r), minus the motion of every frame entered, from each frame's [`PhysicsFrame.State`](/docs/reference/containers/physics-frame#state).

### ShiftOrigin [#shiftorigin]

```csharp
public static void ShiftOrigin(PhysicsFrame frame, Vector3 origin);
```

Move `frame`'s floating origin to the frame-local point `origin` (D19): its root, and with it everything in the frame, moves in simulation space so that point sits at Unity's origin. Frame-local coordinates do not change, so nothing on the wire does. The pose history and interpolation buffers of the entities in the frame are moved with it, and [`PhysicsFrame.Shifted`](/docs/reference/containers/physics-frame#shifted) reports the delta for anything else. Worker only: a client renders every frame at its world pose.

### SourceOf [#sourceof]

```csharp

```

The collider a frame's interior copy was made from (D12): a raycast inside a frame hits the copies, and game code that looks for components on what it hit (a seat, a door button) wants the original on the carrier. Returns `hit` itself when it is not a copy.

### InSimulationPose [#insimulationpose]

```csharp
public static bool InSimulationPose(Container space);
```

Whether `space`'s frame root is at the identity pose right now, so a position read from a transform inside it is frame-local: always on a worker, and on a client during a prediction step ([`BeginSimulation`](#beginsimulation)). False for the scope's own space.

### PoseForRender [#poseforrender]

```csharp
public static void PoseForRender();
```

Client: put every frame root at its frame's world pose, outermost frames first, so the camera sees one world. Called by [`NebulaClient`](/docs/reference/client/nebula-client) every rendered frame after remote entities were interpolated.

Client: put `space`'s frame root back at the identity pose for a prediction step, so the predicted pawn simulates exactly as its worker does (D11). Pair with [`EndSimulation`](#endsimulation).
