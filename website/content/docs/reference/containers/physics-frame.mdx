A container's own physics frame: a local physics scene in which the container stands still (`docs/container-tree.md` §3). Everything the container holds is parented under [`Root`](#root), so in simulation space (every worker, and a client while it predicts) positions inside the frame are container-local and "down" is the container's own down.

### Origin [#origin]

```csharp
public Vector3 Origin { get; }
```

The frame's floating origin (`docs/container-tree.md` D19): the frame-local point that sits at Unity's origin in simulation space. Zero until the worker moves it with [`PhysicsFrames.ShiftOrigin`](/docs/reference/containers/physics-frames#shiftorigin); a planet's frame is large, and physics a few thousand kilometres from Unity's origin would be imprecise. A client keeps one too, near what it predicts in the frame, by the same rule ([`PhysicsFrames.BeginSimulation`](/docs/reference/containers/physics-frames#beginsimulation)).

### KeepOriginLevel [#keeporiginlevel]

```csharp
public bool KeepOriginLevel { get; set; }
```

The worker's automatic origin shifts ([`PhysicsFrames.AutoShift`](/docs/reference/containers/physics-frames#autoshift)) move this frame's origin across, never up or down. Set by a planar chunk grid hosted in the frame (`docs/container-tree.md` D22), whose columns, like a planar root grid's, never shift vertically; a game may set it for a frame of its own. [`PhysicsFrames.ShiftOrigin`](/docs/reference/containers/physics-frames#shiftorigin) called directly still moves the origin wherever it is told.

### UseRenderOrigin [#userenderorigin]

```csharp
public bool UseRenderOrigin { get; set; } = true;
```

Whether this frame may be drawn about a render origin near the camera (D25). On by default; a game turns it off for a frame it poses itself. A frame whose content stays near its own origin (a ship's) never uses one whatever this says, as long as the anchor stays within [`PhysicsFrames.RenderOriginThreshold`](/docs/reference/containers/physics-frames#renderoriginthreshold).

### RenderOrigin [#renderorigin]

```csharp
public Vector3 RenderOrigin { get; }
```

The frame-local point the frame is drawn about on a rendering client (D25): zero while the render anchor is near the frame's own origin, else the anchor's frame-local position snapped to [`PhysicsFrames.RenderOriginStep`](/docs/reference/containers/physics-frames#renderoriginstep). Always zero on a worker.

### RenderPosition [#renderposition]

```csharp
public Vector3 RenderPosition { get; }
```

Where the frame is drawn: its carrier's position as [`PhysicsFrames.PoseForRender`](/docs/reference/containers/physics-frames#poseforrender) last posed it (on a worker, and before the first pose, the carrier's current one). Read this rather than `Root.position`, which under a render origin is composed in float through the turned origin.
