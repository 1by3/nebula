Lookup for portals (`docs/portals.md` D1): the [`Portal`](/docs/reference/containers/portal) components on this process, on a client what the network gateway has told it about the portals near it, and the link poses between scopes ([`Map`](#map), [`Turn`](#turn)). ## Events

### Crossed [#crossed]

```csharp
public static event Action<NetworkIdentity, ulong, ulong, ulong> Crossed;
```

Raised on this process when an entity crossed between two scopes through a portal: on a worker for every committed member, on a client when the entity's container change arrived and was carried through the link. [`Portal.Crossed`](/docs/reference/containers/portal#crossed) says the same for one portal, where its component is known to the process (a client may not have loaded the content a portal stands in). Arguments: the entity, the portal's derived id (0 when only an instance's pose related the scopes), the scope it left and the scope it entered.

### SlotChanged [#slotchanged]

Raised on a client when a scope gained a rendering-layer slot (arguments: the scope and its single layer bit) or lost it (the bit is 0), after Nebula restamped its renderers. A game re-aims its lights' rendering-layer masks here.

### Map [#map]

```csharp
public static PortalPose Map(ulong from, ulong to, PortalPose pose);
public static Double3 Map(ulong from, ulong to, Double3 position);
```

A pose of scope `from` in scope `to`, carried through the link between them (`docs/portals.md` D39): the position about the faces and in double, the rotation turned. Scopes that no portal and no instance pose relates, and a scope with itself, return the pose unchanged. For an instance a template portal built this is its pose against its host ([`InstancePoses`](/docs/reference/containers/instance-poses)), which every process learns from lease rows; for a portal with a fixed far side it is the portal's two faces, known to a worker for the links it holds and to a client from the portal records it was sent. Where several portals join the same two scopes, the one whose face is nearest the pose is used.

### TryMap [#trymap]

```csharp
public static bool TryMap(ulong from, ulong to, PortalPose pose, out PortalPose mapped);
```

As [`Map`](#map), but says whether anything relates the scopes: false (and `mapped` the pose unchanged) when no portal and no instance pose does. A scope with itself is related by the identity. For a game that must tell "the same place on the other side" from "no way through" before it carries a pose, a direction or a hold across.

### Turn [#turn]

```csharp
public static Quaternion Turn(ulong from, ulong to);
```

What turns a rotation or direction of scope `from`'s axes into scope `to`'s, for an entity crossing between them through a portal: the identity unless the link between them is turned. A game keeping its own heading or velocity bookkeeping (a pawn's yaw) applies it in a [`Portal.Crossed`](/docs/reference/containers/portal#crossed) handler. It replaces [`InstancePoses.Turn`](/docs/reference/containers/instance-poses#turn) for anything that crosses a portal, and answers for a portal with a fixed far side too.

### PoseOf [#poseof]

```csharp
public static ScopePose PoseOf(ulong scope);
```

A drawn scope's pose against the [`Anchor`](#anchor), composed in double through the link poses along the portals from the anchor (`docs/portals.md` D40, [`ScopePose`](/docs/reference/containers/scope-pose)). The identity for the anchor and for a scope nothing relates to it. This is where the scope is *drawn*: simulation, prediction and every pose a game reads stay in the scope's own upright space. While cameras draw, Nebula has posed the scope's root containers by it (and the cameras by the view's, when the view is not the anchor).

### RenderMatrixOf [#rendermatrixof]

```csharp
public static Matrix4x4 RenderMatrixOf(ulong scope);
```

A matrix that takes a point of `scope`'s own upright space, in drawing space, to where it is drawn (`docs/portals.md` D41). For what a transform cannot carry: meshes a game draws itself with matrices it keeps (`Graphics.RenderMeshInstanced`, a scatter, a decal batch). Multiply the matrix you would draw an unposed instance with by this one (`RenderMatrixOf(scope) * instanceMatrix`), while [`SceneRenderOrigin.Drawing`](/docs/reference/client/scene-render-origin#drawing) runs: "drawing space" is a scene position minus [`SceneRenderOrigin.Offset`](/docs/reference/client/scene-render-origin#offset), which is what the roots Nebula posed are in. A matrix built from a transform read inside `Drawing` already includes the pose and must not be multiplied again. The identity for the anchor and for a scope nothing relates to it.

### DrawWith [#drawwith]

```csharp
public static void DrawWith(Transform transform, ulong scope);
```

Draw `transform` as part of `scope`: while cameras draw, Nebula poses it by the scope's [`PoseOf`](#poseof) as it poses the scope's root containers, and puts it back afterwards. For what a game keeps outside every container but places in a scope's own space: a light that follows the local player's head, an effect between a hand and what it holds. Without it such a thing is drawn unposed, away from the scope it belongs to, whenever that scope is not the [`Anchor`](#anchor). Pass 0 to stop. A transform already under something posed is left to it; a destroyed one is forgotten.

### KeepUnposed [#keepunposed]

```csharp
public static void KeepUnposed(Camera camera, bool keep = true);
```

Keep `camera` where the game put it while Nebula draws (`keep` false puts it back with the rest). When the view is not the [`Anchor`](#anchor), Nebula moves every camera that draws by the view's pose; a camera that looks at something of its own rather than the world (a portrait of the player's avatar in a corner of space, a preview rendered to a texture) would be moved off it.

### RenderingLayerOf [#renderinglayerof]

```csharp
public static uint RenderingLayerOf(ulong scope);
```

The rendering-layer bit (a single bit of [`NebulaConfig.ScopeRenderingLayers`](/docs/reference/core/nebula-config#scoperenderinglayers)) a drawn scope holds, or 0 when slots are off, the scope is not drawn, or more scopes are drawn than there are bits (`docs/portals.md` D42). Nebula stamps this bit, and only this bit of the reserved mask, on its static content, its chunks' content and its entities' renderers; use it in a light's rendering-layer mask and a portal's masks.

### StampRenderingLayer [#stamprenderinglayer]

```csharp
public static void StampRenderingLayer(Transform root, ulong scope);
```

Stamp the scope's rendering-layer bit on every renderer under `root`: for content a game adds to a scope after Nebula stamped it (a prop built under a chunk's content root later, a renderer added to an entity). Does nothing when slots are off. Nothing outside the reserved bits changes.
