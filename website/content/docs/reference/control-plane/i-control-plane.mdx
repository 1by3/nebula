Provides process registration, container assignments with epochs, and game-defined settings. Use [`ControlPlaneHost`](/docs/reference/control-plane/control-plane-host) on the orchestrator and [`RemoteControlPlane`](/docs/reference/control-plane/remote-control-plane) on workers and gateways of a mesh. Use [`LocalControlPlane`](/docs/reference/control-plane/local-control-plane) for tests and single-process runs. Call [`Tick`](#tick) to receive callbacks on the main thread. Do not use the control plane for per-tick entity state.

The shared simulation scopes that have been activated ([`ActivateScope`](#activatescope)), one row per key, mirrored to every role. The public world has no row. Design of record: `docs/scope-activation.md`.

### Settings [#settings]

```csharp
IReadOnlyDictionary<string, string> Settings { get; }
```

Mesh-wide live settings: string key/values Nebula attaches no meaning to. The orchestrator seeds them (`-nebula-settings k=v,k=v`), the dashboard edits them, and game code on a worker may write them. They are the game's low-volume coordination channel across workers (e.g. a spawn budget every worker reconciles against); never per-tick state.

### ActivateScope [#activatescope]

```csharp
void ActivateScope(ScopeActivationRequest request);
```

Ask the mesh for a shared simulation scope by key, creating its containers from [`ScopeActivationRequest.Definition`](/docs/reference/control-plane/scope-activation-request#definition) the first time. Idempotent: the first caller creates the rows, every later caller with the same definition changes nothing, and a caller with a \*different\* definition under the same key is refused so two worlds never share one scope. A game-supplied unique key is how a private copy is asked for; there is no separate call.

Like every other control-plane write this is fire and forget: the answer is the [`Scopes`](#scopes) row, which appears on this process (and on every other) once the orchestrator has applied it. Poll it with [`ControlPlaneExtensions.FindScope`](/docs/reference/control-plane/control-plane-extensions#findscope) and ask whether it can be entered with [`ControlPlaneExtensions.IsScopeReady`](/docs/reference/control-plane/control-plane-extensions#isscopeready).

### RemoveScope [#removescope]

```csharp
void RemoveScope(string scopeKey);
```

Drop a scope's row, its durable claim and the lease rows of its containers. The mechanism only: when a scope should go is the game's or NEB-240's decision, and entities still in it are not moved.

### EnsureRuntimeContainer [#ensureruntimecontainer]

```csharp
void EnsureRuntimeContainer(string containerId, Bounds bounds, string workerId, InstanceContainerInfo instance = null);
```

Make sure a lease row exists for a runtime container, carrying its box (absolute coordinates) and, when `workerId` is given, already assigned to that worker (epoch 1, active), so the worker that asked for the container owns it from the first change anyone sees. A no-op when the row exists: whoever asked first wins, and the second caller sees the row on the next change.

### TouchContainer [#touchcontainer]

```csharp
void TouchContainer(string containerId);
```

Stamp a lease row's [`LeaseInfo.UpdatedAt`](/docs/reference/control-plane/lease-info#updatedat) without changing anything else: a worker that still wants a runtime container it does not own says so, and the owner reads the age before retiring the box.

### PinContainer [#pincontainer]

```csharp
void PinContainer(string containerId, string workerId);
```

Pin a carried container to `workerId`: worker, epoch and [`LeaseState.Pinned`](/docs/reference/control-plane/lease-state#pinned) in one change, so no subscriber ever sees the lease assigned but not yet pinned (the carrier's worker would reclaim it). Unpin with [`SetLeaseState`](#setleasestate).

### SetContainerHint [#setcontainerhint]

```csharp
void SetContainerHint(string containerId, in ContainerHint hint);
```

Attach a balancing hint to a container, creating the lease row if it does not exist yet: the game (or the dashboard) telling the planner something it cannot measure while the mesh runs. The row outlives an orchestrator restart, and the value wins over whatever was baked. Setting [`ContainerHint.Default`](/docs/reference/containers/container-hint#default) clears the runtime hint and lets the baked one stand again.
