The control plane's state machine: registrations, heartbeats, leases with epochs and settings, kept in plain lists in this process. Changes are applied synchronously and [`Changed`](#changed) fires on the next [`Tick`](#tick). On its own it serves single-process runs and tests; [`ControlPlaneHost`](/docs/reference/control-plane/control-plane-host) wraps it on the orchestrator, where it is the source of truth every [`RemoteControlPlane`](/docs/reference/control-plane/remote-control-plane) mirrors.

### ActivateScope [#activatescope]

```csharp
public void ActivateScope(ScopeActivationRequest request);
```

Make the scope named by `request` exist, or leave the one that already exists alone. Called on the orchestrator's main thread, which serialises it against every other control-plane write, so the check and the create are one step; the durable claim ([`IScopeStore`](/docs/reference/control-plane/i-scope-store)) makes the same hold across orchestrator runs.

### SetScopeState [#setscopestate]

```csharp
public void SetScopeState(string scopeKey, string state);
```

Move a scope to another lifecycle state ([`ScopeState`](/docs/reference/control-plane/scope-state)). The orchestrator's sweep is the only caller in Nebula: it is the single writer of the machine, which is what keeps the ordering guarantees (`docs/scope-lifecycle.md`). The acknowledgements of the previous step are dropped with the change.

### AckScopePart [#ackscopepart]

```csharp
public void AckScopePart(string scopeKey, string containerId, string phase, int count, string workerId);
```

A worker reporting that it finished the step the scope is in for one of its containers ([`ScopePhase`](/docs/reference/control-plane/scope-phase)). Recorded on the row, so the orchestrator's next sweep sees it and every other role can watch the progress. The container must be one of the scope's live parts ([`ScopeLifecycle.CollectParts`](/docs/reference/control-plane/scope-lifecycle#collectparts)): named by the row, or leased under the scope's key. An ack for any other container, or in a phase that does not match the scope's state, is dropped: it belongs to a step that has already ended.

### RemoveScope [#removescope]

```csharp
public void RemoveScope(string scopeKey);
```

Drop a scope row, its claim and the lease rows of its containers. The explicit way out, whatever state the row is in.
