title: Running locally
description: Build the player, run the whole mesh on one machine, watch it on the dashboard, and stop it.
---

Run the commands on this page from a Unity project where you have already run `nebula init`. You can also run the same operations from the **Nebula** menu in the Unity Editor.

## Build

```bash
nebula build
nebula build --linux
```

To build the game for your current platform, run `nebula build`. The command reads the required Unity version from `ProjectSettings/ProjectVersion.txt`. It finds that version through Unity Hub, `NEBULA_UNITY`, or the path saved by `nebula config unity`.

On Windows, the default output is `Builds/Win64/Nebula.exe`. Set `executable` in `nebula.json` to change the base name. To build a Linux dedicated server, run `nebula build --linux`. This command writes the server to `Builds/Linux64` and creates `Builds/nebula-linux.tar.gz` for deployment.

You can keep the project open in the Unity Editor while you build. The CLI copies the project to `~/.nebula-cli/scratch/<project>`, builds the copy, and writes the result to your project's `Builds/` folder.

The CLI prints compiler errors and lines tagged `[nebula]`. To read the complete build log, open `Builds/unity-build.log`. If a running mesh has locked the previous build, run `nebula build --stop-mesh` to stop it before building.

## Start

```bash
nebula start --open-ui
nebula start --workers 2 --bots 2
```

When you run `nebula start`, the CLI:

1. Starts a local SpacetimeDB if none answers on `mesh.spacetimeUri` from `nebula.json` (logs to `Builds/<platform>/Logs/spacetimedb.log`).
2. Publishes the control-plane module with fresh data (`--skip-publish` to keep the tables).
3. Launches the orchestrator from the last build. The orchestrator launches the gateway and the number of workers set by `--workers`. It then assigns each container to a worker.
4. Launches `--bots` bot clients.
5. Waits for the dashboard and prints how to join.

Set local defaults in the `mesh` section of `nebula.json`. To build before starting, add `--build`.

### Joining

To join from the Unity Editor, enter Play mode. `NebulaBootstrap.EditorRole` uses `Client` by default.

To join from a standalone build on Windows, run:

```bash
Builds\Win64\Nebula.exe -nebula-role client -nebula-name Player
```

On the title screen, select the gateway and enter a display name. Select **Local** to use `127.0.0.1:7000`. Press Escape during the game to disconnect or choose another gateway.

To connect without the title screen, pass `-nebula-gateway <address:port>` or `-nebula-connect`. Bot clients also connect without showing the title screen.

### Test with bots and server-driven entities

Use bots to test the complete client path. Use server-driven entities to test worker simulation without starting more client processes.

| | Bot | Server-driven entity |
| --- | --- | --- |
| Start it with | `nebula start --bots N` | `NebulaWorker.SpawnServerDriven` in your game code |
| What it is | A headless client that connects through the gateway, predicts, and corrects its state like a player | A networked entity with no owning client, simulated by its authoritative worker |
| Runtime cost | One Unity player process | One simulated entity |
| Use it for | Testing the complete client connection, prediction, and reconciliation path | Testing server-side entity load |

Your game must provide bot input and server-driven behavior. Nebula does not provide an NPC implementation. See [Spawning](/docs/guides/spawning) for the server-driven API.

The legacy `--npcs N` option only sets a mesh setting named `npcs`. It does not spawn anything. Use it only when your game reads that setting.

## Watch

```bash
nebula status
nebula logs w1 --follow
nebula logs gateway -n 200
```

Run `nebula status` to list workers, their assigned containers, entity counts, and recent orchestrator events.

Run `nebula logs <role>` to read a log. Use `orchestrator`, `gateway`, `w1` through `wN`, or `bot1` and later bot numbers as the role. The CLI stores logs in the build's `Logs/` folder.

To inspect a local mesh in a browser, open `http://localhost:7080/`. The dashboard shows the gateway address, workers, entity counts, tick times, heartbeat ages, container assignments, settings, and recent events.

Use the dashboard controls to add a worker, drain and remove a worker, stop a worker to test recovery, or rebalance containers. You can also perform these operations through the [dashboard HTTP API](/docs/guides/orchestrator-and-dashboard).

If your scene includes `NebulaDebugOverlay`, press F3 to show or hide it. The overlay displays the tick, round-trip time (RTT), input lead, current container, current worker, observed handovers, and container assignments.

## Stop

```bash
nebula stop
nebula stop --spacetime
```

Run `nebula stop` to stop every process from the build and any SpacetimeDB process that `nebula start` started. Add `--spacetime` to stop a SpacetimeDB process that was already running before you started the mesh.

## From the Editor

Use the **Nebula** menu in the Unity Editor to run the same development tasks:

- Use **Control Plane** to start or stop local SpacetimeDB, publish the module, or regenerate its C# bindings.
- Use **Mesh** to start or stop a local mesh from the latest build, open the dashboard, or launch another client.
- Use **Build** to create a Windows player or Linux dedicated server.
