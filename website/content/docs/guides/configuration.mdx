---
title: Configure Nebula
description: Set project defaults in NebulaConfig and nebula.json, then override them for individual processes or CLI runs.
---

Use these configuration layers:

1. Edit `NebulaConfig` in Unity to configure the runtime.
2. Edit `nebula.json` to configure the CLI for one project.
3. Run `nebula config` to store machine-specific paths and credentials.
4. Pass a command-line option when you need to override a value for one run.

## Configure the runtime in Unity

Open `Assets/Resources/NebulaConfig.asset` in the Inspector. Every Nebula process loads this asset, so the client, workers, gateway, and orchestrator use the same defaults.

Run `nebula init` to create the asset. For every field and its current default, see the [`NebulaConfig` reference](/docs/reference/core/nebula-config).

### Game content and world loading

| Field | Default | What to set |
| --- | --- | --- |
| `GameScene` | `Arena` | Select the scene that contains your containers and gameplay. |
| `NetworkPrefabs` | empty | Add every prefab that Nebula can spawn. The list index becomes the prefab ID sent over the network. |
| `WorldManifest` | none | Assign a baked manifest when you [partition a large world](/docs/guides/world-partition). Leave it empty to load the whole game scene. |
| `ClientLoadRadiusCells` | `1` | Choose how many cells clients load around their pawn. A value of `1` loads a 3 × 3 × 3 group of cells. |
| `WorkerLoadRingCells` | `1` | Choose how many neighboring cell rings a worker loads around its leased cells. |
| `OriginShiftThresholdCells` | `4` | Move the floating origin after the client pawn or worker lease center crosses this many cells. |
| `SceneEntityGraceSeconds` | `2` | Wait this long before a new container owner spawns scene entities that did not arrive in a handover. |

### Connections and processes

| Field | Default | What to set |
| --- | --- | --- |
| `GatewayAddress`, `GatewayPort` | `127.0.0.1`, `7000` | Set the address and port clients use to reach the gateway. |
| `WorkerBasePort` | `7100` | Set the base for worker ports. Worker 1 uses `7101`, worker 2 uses `7102`, and so on. |
| `WorkerAdvertiseAddress` | `127.0.0.1` | Set the address workers advertise to peers and the gateway. |
| `SpacetimeUri`, `SpacetimeDatabase` | local server, `nebula` | Select the SpacetimeDB server and database used as the control plane. |
| `UseLocalControlPlane` | `false` | Enable the in-process control plane only when all server roles run in one process, such as in a test. |
| `WorkerCount` | `4` | Set the initial number of workers. |
| `WorkerHost` | `process` | Use `process` for child processes or `hetzner` for one Hetzner Cloud VM per worker. |
| `DashboardPort` | `7080` | Set the dashboard port. Use `0` to disable the dashboard. |

### Failure and handover timing

| Field | Default | What to set |
| --- | --- | --- |
| `WorkerHeartbeatSeconds` | `1` | Choose how often each worker reports that it is alive. |
| `WorkerTimeoutSeconds` | `5` | Choose how long the orchestrator waits before it treats a silent worker as dead. |
| `DeadWorkerReplaceDelaySeconds` | `8` | Wait this long before starting a replacement for a dead worker. |
| `WorkerDrainTimeoutSeconds` | `10` | Give a retiring worker this long to transfer its entities before stopping it. |
| `GhostBandMargin` | `4` m | Create a ghost copy when an entity comes within this distance of a neighboring container. |
| `HandoverHysteresis` | `0.35` m | Require an entity to move this far into a new container before transferring authority. |
| `GhostLingerSeconds` | `2` | Keep a ghost copy for this long after it leaves the ghost band. |

### Client update rates and prediction

| Field | Default | What to set |
| --- | --- | --- |
| `InterestNearRadius` | `30` m | Send entity state every tick inside this distance from the client's pawn. |
| `InterestFarRadius` | `80` m | Use the middle update rate between the near and far distances. |
| `InterestMidDivisor` | `4` | Send every fourth tick in the middle distance band. Use `1` to send every tick. |
| `InterestFarDivisor` | `12` | Send every twelfth tick beyond the far distance. Clients without a pawn also receive this rate. |
| `InterpolationDelayTicks` | `3` | Render remote entities this many ticks behind the latest received state. |
| `InputLeadMarginTicks` | `2` | Add this many ticks to half the measured round-trip time when scheduling input. |
| `InputLeadTargetTicks` | `3` | Keep client input this many ticks ahead when it arrives at the worker. |
| `InputLeadMaxAdjustTicks` | `30` | Limit how far the client can increase its input lead. |

Nebula runs at 60 ticks per second. `NetworkTime.TickRate` is a constant, not a configuration field.

## Override runtime values on the command line

Use runtime options when you start a Nebula role by hand. The CLI and orchestrator add these options for the processes they manage.

Pass options as `-name value`. Pass a Boolean option without a value to enable it.

| Option | Used by | What it does |
| --- | --- | --- |
| `-nebula-role client\|worker\|gateway\|orchestrator` | all roles | Select one or more comma-separated roles. Do not combine the client and worker roles. Use `services` as an alias for gateway and orchestrator. |
| `-nebula-scene <name>` | all roles | Override `GameScene`. |
| `-nebula-gateway <address:port>` | client, worker, orchestrator | Set the gateway address. A client connects immediately when you supply this option. |
| `-nebula-connect` | client | Connect to the configured gateway without showing the title screen. |
| `-nebula-name <name>` | client | Set the player's display name. |
| `-nebula-bot` | client | Mark this headless client as a bot. Your game must provide its input behavior. |
| `-nebula-worker-id <id>` | worker | Set the worker ID. The orchestrator normally supplies it. |
| `-nebula-worker-index <number>` | worker | Set the worker index. The orchestrator normally supplies it. |
| `-nebula-port <port>` | worker | Set the worker's listening port. |
| `-nebula-advertise <address\|auto>` | worker, gateway, orchestrator | Set the address advertised to other processes. Use `auto` to select the first private IPv4 address. |
| `-nebula-spacetime <url>` | server roles | Override the SpacetimeDB server URL. |
| `-nebula-database <name>` | server roles | Override the control-plane database name. |
| `-nebula-local-control-plane` | server roles | Use the in-process control plane. |
| `-nebula-workers <number>` | orchestrator | Set the initial worker count. |
| `-nebula-settings key=value,key=value` | orchestrator | Add game-defined, mesh-wide settings to the control plane. |
| `-nebula-dashboard-port <port>` | orchestrator | Set the dashboard port. |
| `-nebula-dashboard-bind <address\|+>` | orchestrator | Bind the dashboard to one address. Use `+` to bind all interfaces. |
| `-nebula-host process\|hetzner` | orchestrator | Select where workers run. |
| `-nebula-worker-exe <path>` | orchestrator | Select the executable used to start workers and the gateway. |
| `-nebula-build-dir <path>` | orchestrator | Serve worker build files from this directory at `/build/`. |
| `-nebula-ghost-band <metres>` | worker | Override `GhostBandMargin`. |
| `-nebula-hysteresis <metres>` | worker | Override `HandoverHysteresis`. |
| `-nebula-reset false` | orchestrator | Keep existing control-plane rows. The default resets this temporary registry state. |
| `-nebula-verbose` | all roles | Write debug-level logs. |

Cloud deployments also use `-nebula-cloud-*` options. Let `nebula deploy` supply them unless you run the orchestrator yourself. See [Deploy to Hetzner Cloud](/docs/deploy/hetzner) for the supported values.

Unity's standard `-batchmode`, `-nographics`, and `-logFile <path>` options also apply.

## Configure one project in nebula.json

Run `nebula init` to create `nebula.json` at the Unity project root. The CLI reads this file for local and cloud defaults.

```json title="nebula.json"
{
  "nebula": "0.1.0",
  "executable": "Nebula",
  "mesh": {
    "workers": 4,
    "npcs": 0,
    "dashboardPort": 7080,
    "gatewayPort": 7000,
    "spacetimeUri": "http://127.0.0.1:3000",
    "database": "nebula"
  },
  "deploy": {
    "target": "hetzner",
    "meshName": "nebula",
    "database": "my-game",
    "workers": 4,
    "npcs": 0
  }
}
```

| Key | What it controls |
| --- | --- |
| `nebula` | Records the CLI version that last wrote the file. `nebula init` updates it. |
| `executable` | Sets the base name of builds produced by `NebulaBuild`, such as `Nebula.exe` or `Nebula.x86_64`. |
| `mesh.workers` | Sets the default worker count for `nebula start`. |
| `mesh.dashboardPort`, `mesh.gatewayPort` | Set the ports used by a local mesh and by deployment firewalls. |
| `mesh.spacetimeUri`, `mesh.database` | Select the local control-plane server and database. |
| `deploy.target` | Selects the deployment provider. This release supports `hetzner`. |
| `deploy.meshName` | Sets the label and name prefix used for cloud resources. |
| `deploy.database` | Selects the deployed control-plane database. |
| `deploy.workers` | Sets the default worker count for `nebula deploy`. |
| `deploy.workerType`, `deploy.orchestratorType`, `deploy.location` | Override the machine types and region stored in the CLI's machine config. |

The `mesh.npcs` and `deploy.npcs` keys seed a game setting named `npcs`. Nebula does not create non-player characters or assign meaning to this setting. Leave both values at `0` unless your game reads the setting.

## Configure this computer

Run `nebula config` commands to store machine-specific paths and credentials in `~/.nebula-cli/config.json`:

```bash
nebula config source
nebula config unity
nebula config hetzner
nebula config spacetime
nebula config show
```

`nebula config show` masks the saved Hetzner token. On Unix, the CLI creates the file with permissions `0600`. Set `HCLOUD_TOKEN` to override the saved token.

Set `NEBULA_CLI_HOME` to move the entire `~/.nebula-cli` directory. The directory also contains the CLI binary, a downloaded SDK checkout when you have not configured a source checkout, and temporary project copies used during builds.
