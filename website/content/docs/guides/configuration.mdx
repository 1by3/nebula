---
title: Configure Nebula
description: Set project defaults in NebulaConfig and nebula.json, then override them for individual processes or CLI runs.
---

Use these configuration layers:

1. Edit `NebulaConfig` in Unity to configure the runtime.
2. Edit `nebula.json` to configure the CLI for one project.
3. Run `nebula config` to store machine-specific paths and credentials.
4. Pass a command-line option when you need to override a value for one run.

## Configure the runtime in Unity

Open `Assets/Resources/NebulaConfig.asset` in the Inspector. Every Nebula process loads this asset, so the client, workers, gateway, and orchestrator use the same defaults.

Run `nebula init` to create the asset. For every field and its current default, see the [`NebulaConfig` reference](/docs/reference/core/nebula-config).

### Game content and world loading

| Field | Default | What to set |
| --- | --- | --- |
| `GameScene` | `Arena` | Select the scene that contains your containers and gameplay. |
| `NetworkPrefabs` | empty | Add every prefab that Nebula can spawn. The list index becomes the prefab ID sent over the network. |
| `WorldManifest` | none | Assign a baked manifest when you [partition a large world](/docs/guides/world-partition). Leave it empty for a single scene or a `RuntimeWorld`. |
| `RuntimeWorld` | none | Assign a `WorldDefinition` for a procedural world whose containers are registered at runtime. Leave `WorldManifest` empty. |
| `ClientLoadRadiusCells` | `1` | Choose how many cells clients load around their pawn. A value of `1` loads a 3 × 3 × 3 group of cells. |
| `WorkerLoadRingCells` | `1` | Choose how many neighboring cell rings a worker loads around its leased cells. |
| `OriginShiftThresholdCells` | `4` | Move the floating origin after the client pawn or worker lease center crosses this many cells. |
| `SceneEntityGraceSeconds` | `2` | Wait this long before a new container owner spawns scene entities that did not arrive in a handover. |

### Editor dev loop

These fields change only what pressing Play in the Editor starts. Builds ignore them. See [Iterate without building](/docs/getting-started/running-locally#iterate-without-building-multiplayer-play-mode).

| Field | Default | What to set |
| --- | --- | --- |
| `EditorRunMode` | `Mesh` | `Mesh` runs `NebulaBootstrap.EditorRole` against a mesh started with `nebula start`. `MultiplayerPlayMode` lets a Multiplayer Play Mode virtual player host the server while the main Editor joins as a client, with no build. |
| `EditorPersistence` | `DevSaveFile` | `DevSaveFile` keeps the dev server's saved entities in `Library/Nebula/DevSaves/world.bin` between Play sessions. `InMemory` starts every Play from an empty world. |
| `EditorPortOffset` | `50` | Add this to the gateway, worker and dashboard ports in `MultiplayerPlayMode`, so a mesh started with `nebula start` can run at the same time. `0` uses the configured ports. |

### Connections and processes

| Field | Default | What to set |
| --- | --- | --- |
| `GatewayAddress`, `GatewayPort` | `127.0.0.1`, `7000` | Set the address and port clients use to reach the gateway. |
| `WorkerBasePort` | `7100` | Set the base for worker ports. Worker 1 uses `7101`, worker 2 uses `7102`, and so on. A worker started with `-nebula-port`, or with the `PORT` environment variable set, listens on that port instead. |
| `WorkerAdvertiseAddress` | `127.0.0.1` | Set the address workers advertise to peers and the gateway. |
| `WebClients` | `true` | Let the standalone gateway accept clients from a Unity Web build over WebRTC. See [Build for the web](/docs/guides/web-builds). |
| `WebPort` | `0` | Set the gateway's TCP port for WebRTC offers and the web build. `0` uses the same number as `GatewayPort`. A web client connects to this port. |
| `WebRtcPort` | `0` | Set the gateway's UDP port for WebRTC traffic. `0` uses `GatewayPort + 1`. |
| `ControlPlaneUrl` | `http://127.0.0.1:7080/` | Set the orchestrator's dashboard address for a worker or gateway you start by hand. The orchestrator passes it to the processes it launches. |
| `MeshToken` | empty | Set a shared secret that workers and gateways present to the orchestrator, and to each other when they connect. Empty means no token and every peer is accepted. `nebula deploy` generates one per deployment. |
| `UseLocalControlPlane` | `false` | Enable the in-process control plane only when all server roles run in one process, such as in a test. |
| `DatabaseUrl` | empty | Select where the orchestrator keeps the control plane and saved entities: `sqlite:<file>`, `postgres://...`, `file:<folder>`, or `memory`. Empty means a default next to the process. |
| `WorkerCount` | `4` | Set the number of workers to start with. |
| `WorkerHost` | `process` | Use `process` for child processes, `hetzner` for one Hetzner Cloud VM per worker, or `cloud` to request machines from a hosting platform's resource API. See [Choose where workers run](/docs/guides/orchestrator-and-dashboard#choose-where-workers-run). |
| `OrchestratorSpawnsGateway` | `true` | Let the orchestrator start one gateway (`gw1`) as a child process. Turn it off when whoever runs the gateway fleet starts every gateway. |
| `DashboardPort` | `7080` | Set the dashboard port. Use `0` to disable the dashboard. |

### Autoscaling

The orchestrator keeps the worker count between `MinWorkers` and `MaxWorkers` from the tick time workers report, and
checks every change against a dry run of the assignment policy first. See
[Autoscale](/docs/guides/orchestrator-and-dashboard#autoscale).

| Field | Default | Command line | `nebula.json` | What to set |
| --- | --- | --- | --- | --- |
| `MinWorkers` | `1` | `-nebula-min-workers <n>` | `mesh.minWorkers` | Set the fewest workers autoscaling leaves running. `0` allows scaling to zero: the first player then waits for a worker to boot. |
| `MaxWorkers` | `32` | `-nebula-max-workers <n>` | `mesh.maxWorkers` | Set the most workers the orchestrator will ever run. |
| `AutoScale` | `true` | `-nebula-autoscale true\|false` | — | Turn autoscaling off to keep `WorkerCount` workers running whatever the load. |
| `ScaleOutUtilization` | `0.7` | — | — | Grow when the busiest worker spends more than this fraction of its tick budget simulating (`0.7` = 11.7 ms of a 16.7 ms tick). |
| `ScaleInUtilization` | `0.3` | — | — | Shrink when the mesh's mean utilization stays under this fraction and the survivors would stay under `ScaleOutUtilization`. |
| `ScaleHoldSeconds` | `30` | — | — | Choose how long a condition must hold before a worker is added or retired. Only one change happens per hold. |
| `ScaleWindowSeconds` | `20` | — | — | Set the length of the rolling per-worker tick-time window whose 90th percentile is the scaling signal. |
| `ScaleMinGain` | `0.1` | — | — | Require this much predicted improvement in the busiest worker before adding a worker or re-dealing containers. Below it the orchestrator reports the hot container as unsplittable instead of growing. |
| `SeamGraceMeters` | `10` m | — | — | Leave a container alone for a pass when a player is within this distance of a seam that would move. Configured but not enforced yet: occupancy reports carry counts, not positions. |
| `IdlePoolSeconds` | `0` | `-nebula-idle-pool <seconds>` | `mesh.idlePoolSeconds` | Keep a retired worker parked for at most this long on a host that parks. `0` means as long as it is already paid for (Hetzner: the rest of the billed hour). See [Idle pool](/docs/guides/orchestrator-and-dashboard#idle-pool). |

The fields without a command-line option are set on the `NebulaConfig` asset. `nebula start --workers N` fixes the
count (`min` = `max` = `N`); `nebula start --min A --max B` opens the band, starts the mesh at `A`, and lets
autoscaling grow it towards `B`.

### Failure and handover timing

| Field | Default | What to set |
| --- | --- | --- |
| `WorkerHeartbeatSeconds` | `1` | Choose how often each worker reports that it is alive. |
| `WorkerTimeoutSeconds` | `5` | Choose how long the orchestrator waits before it treats a silent worker as dead. |
| `DeadWorkerReplaceDelaySeconds` | `8` | Wait this long before starting a replacement for a dead worker. |
| `WorkerDrainTimeoutSeconds` | `10` | Give a retiring worker this long to transfer its entities before stopping it. |
| `SessionReclaimSeconds` | `30` | Keep a player's pawn this long after the player's link drops, so the player can reconnect (through any gateway of the mesh) with the same session and pawn. `0` despawns at once. See [Sessions and reconnection](/docs/guides/authentication#sessions-and-reconnection). |
| `SingleSessionPerPlayer` | `true` | Gateways coordinate one connection per identity. A replacement waits for the previous gateway to acknowledge disconnection; admission fails if coordination is unavailable. Turn it off on every gateway to allow multiple sessions per identity. See [One connection per player](/docs/guides/authentication#one-connection-per-player). |
| `GatewayDrainReconnectSeconds` | `10` | Tell the clients of a draining gateway that they have this long to reconnect before it closes their links. |
| `GhostBandMargin` | `4` m | Create a ghost copy when an entity comes within this distance of a neighboring container. |
| `HandoverHysteresis` | `0.35` m | Require an entity to move this far into a new container before transferring authority. |
| `GhostLingerSeconds` | `2` | Keep a ghost copy for this long after it leaves the ghost band. |
| `StateHistoryTicks` | `32` | Ticks of pose and `[SyncHistory]` state each worker keeps per entity, for `NetworkIdentity.StateAt`. About half a second at 60 Hz. `0` turns recording off. See [Lag compensation](/docs/guides/lag-compensation). |

### Persistence

Entities carrying a `PersistentEntity` component are saved and restored. See [Persistence](/docs/guides/persistence).

| Field | Default | What it does |
| --- | --- | --- |
| `PersistenceMode` | `auto` | Select the store: `auto` (the orchestrator's database, a worker's `remote` store, or `local` when `UseLocalControlPlane` is on), `database`, `remote`, `local`, `memory`, or `off`. |
| `PersistenceLocalFile` | empty | Set the file the `local` store writes to. Empty uses `<persistentDataPath>/nebula-persistence.bin`. |
| `PersistenceCheckpointSeconds` | `5` | Choose how often an authoritative persistent entity is checkpointed. A change or a move saves sooner. |
| `PersistenceRestoreGraceSeconds` | `3` | Wait this long after gaining a container lease before restoring that container's saved entities. |
| `ScopeIdleRetireSeconds` | `300` | Retire a [simulation scope](/docs/guides/scopes#retiring-and-re-activating-a-scope) that has held nothing for this long: checkpoint its persistent entities, release its containers, and bring it back when the key is activated again. `0` turns retirement off. Never applies to the public world. |
| `ScopeRetireWithEntities` | `false` | Retire an idle scope that no player is in even though it still holds entities, such as saved crates or parked vehicles. See [Retire a world that still holds things](/docs/guides/scopes#retire-a-world-that-still-holds-things). |

### Interest management

[Interest management](/docs/guides/interest-management) decides which entities a client hears about at all. These fields are on `NebulaConfig`; see that guide for the full explanation, the policy API, and the observability fields.

| Field | Default | What it does |
| --- | --- | --- |
| `InterestRadius` | `120` m | How far a client hears about an entity. A prefab's `RelevanceRadius` overrides it per entity. |
| `InterestExitMargin` | `16` m | Extra distance past `InterestRadius` an entity must cross before it leaves a client's set. |
| `InterestLingerSeconds` | `1` s | How long an entity must stay past the exit radius before the client is told to despawn it. |
| `InterestCellSize` | `64` m | Edge length of one interest region. Snapped to an integer divisor of the world's cell size when a world definition exists. |
| `InterestPlanar` | `true` | Regions are infinite columns; height does not affect the region key. Turn off for a volumetric or space game. |
| `InterestEvalHz` | `4` | How often each client's interest set is re-evaluated per second. |
| `InterestSubscribeMargin` | `32` m | Extra distance of regions a gateway subscribes beyond a focus, ahead of a client's exact filter needing them. |
| `InterestRegionLingerSeconds` | `3` s | How long a region stays subscribed after the last client needed it. |
| `InterestLinkLingerSeconds` | `10` s | How long a gateway keeps a worker connection after the last reason to hold it is gone. |
| `InterestResyncSeconds` | `30` s | How often a gateway resends its whole subscription as an audit. |
| `InterestMaxRadius` | `1024` m | Ceiling on a prefab's `RelevanceRadius`, and the farthest a wide entity may reach. Never uncapped: a value of 0 or less is reported and replaced with `InterestRadius`. |
| `InterestMaxFoci` | `8` | Most foci one client may have at once. |
| `InterestHintMaxDistance` | `60` m | How far a client's focus hint may sit from its pawn before it is clamped. |
| `InterestHintMaxHz` | `5` | Most focus hints accepted from one client per second. |
| `InterestMaxExplicitPerClient` | `16` | Most entities one client's policy may subscribe to by ID. |
| `InterestMaxFocusSpeed` | `12` m/s | The fastest a player is expected to travel, used to check `InterestSubscribeMargin`. |
| `PartitionWarnEntities` | `2000` | A worker warns when one container holds more entities than this. `0` disables the warning. |
| `PartitionWarnFilterMs` | `2` ms | A worker warns when per-gateway filtering takes longer than this per tick. `0` disables the warning. |

`NebulaConfig.Validate` checks the interest settings at startup. A non-positive `InterestRadius` or `InterestCellSize` blocks startup. Other invalid values are adjusted, with warnings for most corrections.

- Update-rate bands satisfy `InterestNearRadius <= InterestFarRadius <= InterestRadius`.
- The exit margin is positive, and the subscription margin covers at least one evaluation interval of travel at `InterestMaxFocusSpeed`.
- Region size is aligned to a divisor of the world cell size. A ghost band at least as wide as a region produces a warning; validation does not change the ghost band.
- `ClientLoadRadiusCells` is raised to cover `InterestRadius + InterestExitMargin`. The effective streaming radius, [`NearCells`](/docs/guides/interest-management#one-notion-of-near), also includes movement during removal delays. The runtime allocator uses `NearCells + 1`.
- `InterestMaxRadius` is at least `InterestRadius`. Zero does not disable this limit.

### Gateway extension

See [Extend the gateway](/docs/guides/gateway-extensions) to build and load the class library.

| Field | Default | What to set |
| --- | --- | --- |
| `GatewayExtension` | empty | Your game's code inside the standalone gateway: the extension assembly's file name (next to the gateway executable) or an absolute path. Empty means no extension. |
| `GatewayExtensionType` | empty | Which class to load, only needed when the assembly defines more than one `IGatewayExtension`. |
| `GatewayExtensionOptions` | empty | Options your extension reads with `context.Option(key)`, as `key=value;key=value`. |

These are not numeric knobs and are not clamped: a configured extension that fails to load stops the gateway from starting.

### chunked world

See [Build an infinite runtime world](/docs/guides/infinite-runtime-world) for the full setup.

| Field | Default | What to set |
| --- | --- | --- |
| `ChunkedWorld` | `false` | Turn on the unbounded chunked world: with `RuntimeWorld` assigned, Nebula builds the chunk grid from its cell size, leases chunks around every pawn on workers, keeps the floating origin near the pawn on clients, and raises `NebulaChunks.Loaded`/`Unloading` on every role. |
| `ChunkPlanar` | `true` | Chunks are columns: the grid has one layer at `y = 0` and `RuntimeWorld.CellSize.y` is the column height. Turn off for a volumetric world. |
| `ChunkRetireSeconds` | `30` | Seconds a chunk nobody needs stays leased before the worker retires it. Its persistent contents are checkpointed and restored when the chunk is requested again. |

### Client update rates and prediction

| Field | Default | What to set |
| --- | --- | --- |
| `InterestNearRadius` | `30` m | Forward each available unreliable root update inside this distance from the client's pawn. This throttles update rate for entities already in the client's interest set; it does not decide whether they are in it. See [Interest management](/docs/guides/interest-management). |
| `InterestFarRadius` | `80` m | Use the middle update rate between the near and far distances. |
| `InterestMidDivisor` | `4` | Forward available unreliable root updates on every fourth tick in the middle band. Use `1` to forward each available update. |
| `InterestFarDivisor` | `12` | Forward available unreliable root updates on every twelfth tick beyond the far distance. Clients without a pawn also use this filter. |
| `InterpolationDelayTicks` | `3` | Render remote entities at least this many ticks behind the latest received state. The client adds the lateness it measures on the slowest worker's stream (up to 6 ticks; `NebulaClient.RenderDelayTicks` shows the total). |
| `InputLeadMarginTicks` | `2` | Add this many ticks to half the measured round-trip time when scheduling input. |
| `InputLeadTargetTicks` | `3` | Keep client input this many ticks ahead when it arrives at the worker. |
| `InputLeadMaxAdjustTicks` | `30` | Limit how far the client can increase its input lead. |

Nebula runs at 60 ticks per second. `NetworkTime.TickRate` is a constant, not a configuration field.

These distance filters do not create updates for static entities or unchanged transforms. Reliable root recovery, teleports, and container changes bypass the filter so the last pose can arrive after movement stops. Child component state uses a separate channel. See [NetworkTransform](/docs/guides/network-transform).

## Override runtime values on the command line

Use runtime options when you start a Nebula role by hand. The CLI and orchestrator add these options for the processes they manage.

Pass options as `-name value`. Pass a Boolean option without a value to enable it.

| Option | Used by | What it does |
| --- | --- | --- |
| `-nebula-role client\|worker\|gateway\|orchestrator` | all roles | Select one or more comma-separated roles. Do not combine the client and worker roles. Use `services` as an alias for gateway and orchestrator. |
| `-nebula-scene <name>` | all roles | Override `GameScene`. |
| `-nebula-gateway <address:port>` | client, worker, orchestrator | Set the gateway address. A client connects immediately when you supply this option. |
| `-nebula-connect` | client | Connect to the configured gateway at startup. `NebulaTitleScreen` stays hidden. |
| `-nebula-name <name>` | client | Set the player's display name. |
| `-nebula-bot` | client | Mark this headless client as a bot. Your game must provide its input behavior. A bot does not keep an anonymous identity between runs. |
| `-nebula-auth-token <jwt>` | client | Present this OpenID Connect ID token to the gateway. See [Authentication](/docs/guides/authentication). |
| `-nebula-worker-id <id>` | worker | Set the worker ID. The orchestrator normally supplies it. |
| `-nebula-worker-index <number>` | worker | Set the worker index. The orchestrator normally supplies it. |
| `-nebula-port <port>` | worker | Set the worker's listening port. Without this option, the worker uses the `PORT` environment variable, then `WorkerBasePort + index`. A `PORT` value that is not a port from 1 to 65535 is ignored with a warning. Other roles ignore `PORT`. |
| `-nebula-advertise <address\|auto>` | worker, gateway, orchestrator | Set the address advertised to other processes. Use `auto` to select the first private IPv4 address. |
| `-nebula-control-plane <url>` | worker, gateway | Override `ControlPlaneUrl`. |
| `-nebula-gateway-id <id>` | gateway | Set the gateway's persistent ID (default `gw1`). Give every gateway of a mesh a distinct one. |
| `-nebula-web true\|false` | gateway | Override `WebClients`. |
| `-nebula-web-port <port>`, `-nebula-webrtc-port <port>` | gateway | Override `WebPort` and `WebRtcPort`. |
| `-nebula-web-root <folder>` | gateway | Serve the web build from this folder. Without it, the gateway serves a `Web` folder next to its executable or next to its build folder. |
| `-nebula-web-tls off\|acme` | gateway, orchestrator | Serve the web port over HTTPS with a certificate from an ACME certificate authority, Let's Encrypt by default. The orchestrator passes it to the gateway it starts. See [Serve HTTPS for hosted pages](/docs/guides/web-builds#serve-https-for-hosted-pages). |
| `-nebula-web-tls-dir <folder>`, `-nebula-acme-directory <url>`, `-nebula-acme-email <address>` | gateway, orchestrator | Choose where the certificate and account key are kept, which ACME server issues the certificate, and the contact address it registers. |
| `-nebula-token <secret>` | server roles | Override `MeshToken`. The standalone services also read `NEBULA_MESH_TOKEN`. With a token set, gateways and workers refuse peers that cannot present a credential derived from it. |
| `-nebula-auth-issuers <urls>`, `-nebula-auth-audience <id>`, `-nebula-auth-anonymous true\|false` | gateway, orchestrator | Override `AuthIssuers`, `AuthAudience`, and `AuthAnonymous`. The orchestrator passes them to the gateway it starts. See [Authentication](/docs/guides/authentication). |
| `-nebula-auth-key <secret>` | gateway, orchestrator | Override `AuthSigningKey`, the key anonymous identity tokens and session tokens are signed with. The standalone gateway also reads `NEBULA_AUTH_KEY`. Every gateway of a mesh needs the same key. |
| `-nebula-encrypt-clients true\|false`, `-nebula-require-encryption true\|false` | gateway, orchestrator | Override `EncryptClients` and `RequireEncryption`. The orchestrator passes them to the gateway it starts. See [Encrypt client connections](/docs/deploy/encryption). |
| `-nebula-encryption-cert <file>`, `-nebula-encryption-key <file>`, `-nebula-encryption-store <file>` | gateway, orchestrator | Choose the Privacy-Enhanced Mail (PEM) certificate and key files the gateway presents to clients, and where a generated self-signed certificate is kept. The standalone gateway also reads `NEBULA_ENCRYPTION_CERT` and `NEBULA_ENCRYPTION_KEY` as PEM text. |
| `-nebula-encrypt true\|false`, `-nebula-gateway-fingerprint <hex>` | client | Override `ClientEncryption` and `GatewayFingerprint`: encrypt the link to the gateway, and accept only the certificate with this fingerprint. |
| `-nebula-content-version <number>` | Unity client, gateway | Set `GameContentVersion`. A client announces this number; a gateway checks it. A gateway value of `0` disables the check. See [Replace gateways and workers](/docs/deploy/upgrades). |
| `-nebula-min-content-version <number>` | Unity gateway | Set the oldest accepted game content version. `0` requires an exact match with `GameContentVersion`. |
| `-nebula-single-session true\|false` | gateway, worker, orchestrator | Override `SingleSessionPerPlayer`. The orchestrator passes it to the gateway and workers it starts. |
| `-nebula-database <url>` | orchestrator | Override `DatabaseUrl`. The standalone orchestrator also reads `NEBULA_DATABASE_URL`. |
| `-nebula-local-control-plane` | server roles | Use the in-process control plane. |
| `-nebula-persistence-mode auto\|database\|remote\|local\|memory\|off` | worker, orchestrator | Override `PersistenceMode`. |
| `-nebula-reset-persistence` | orchestrator | Delete every saved entity at startup. |
| `-nebula-persistence-file <path>` | worker, orchestrator | Override `PersistenceLocalFile`. |
| `-nebula-persistence-checkpoint <seconds>` | worker | Override `PersistenceCheckpointSeconds`. |
| `-nebula-scope-idle-retire <seconds>` | orchestrator | Override `ScopeIdleRetireSeconds`. `0` turns scope retirement off. |
| `-nebula-scope-retire-with-entities true\|false` | orchestrator | Override `ScopeRetireWithEntities`. |
| `-nebula-workers <number>` | orchestrator | Set the initial worker count. |
| `-nebula-min-workers <number>`, `-nebula-max-workers <number>` | orchestrator | Override `MinWorkers` and `MaxWorkers`, the autoscaling band. |
| `-nebula-autoscale true\|false` | orchestrator | Override `AutoScale`. |
| `-nebula-idle-pool <seconds>` | orchestrator | Override `IdlePoolSeconds`. |
| `-nebula-settings key=value,key=value` | orchestrator | Add game-defined, mesh-wide settings to the control plane. |
| `-nebula-dashboard-port <port>` | orchestrator | Set the dashboard port. |
| `-nebula-dashboard-bind <address\|+>` | orchestrator | Bind the dashboard to one address. Use `+` to bind all interfaces. |
| `-nebula-host process\|hetzner\|cloud` | orchestrator | Select where workers run. |
| `-nebula-cloud-api <url>`, `-nebula-cloud-deployment-token <token>` | orchestrator | With `-nebula-host cloud`, the resource API and the deployment-scoped token. The standalone orchestrator also reads `NEBULA_CLOUD_API` and `NEBULA_CLOUD_DEPLOYMENT_TOKEN`. See [The cloud worker host](/docs/guides/orchestrator-and-dashboard#the-cloud-worker-host). |
| `-nebula-spawn-gateway true\|false` | orchestrator | Override `OrchestratorSpawnsGateway`. |
| `-nebula-worker-exe <path>` | orchestrator | Select the executable used to start workers and the gateway. |
| `-nebula-build-dir <path>` | orchestrator | Serve worker build files from this directory at `/build/`. |
| `-nebula-ghost-band <meters>` | worker | Override `GhostBandMargin`. |
| `-nebula-hysteresis <meters>` | worker | Override `HandoverHysteresis`. |
| `-nebula-state-history <ticks>` | worker | Override `StateHistoryTicks`. `0` turns state recording off. See [Lag compensation](/docs/guides/lag-compensation). |
| `-nebula-interest-radius <meters>` | gateway, worker | Override `InterestRadius`. See [Interest management](/docs/guides/interest-management). |
| `-nebula-interest-cell <meters>` | gateway, worker | Override `InterestCellSize`. |
| `-nebula-gateway-extension <file>` | gateway | Override `GatewayExtension`. The orchestrator forwards it to the gateway it launches. See [Extend the gateway](/docs/guides/gateway-extensions). |
| `-nebula-gateway-extension-type <Namespace.Class>` | gateway | Override `GatewayExtensionType`. |
| `-nebula-gateway-extension-options key=value;key=value` | gateway | Override `GatewayExtensionOptions`. |
| `-nebula-ext-<key> <value>` | gateway | Override one extension option; read inside the extension with `context.Option(key)`. |
| `-nebula-reset false` | orchestrator | Restore the stored control plane instead of starting empty. The default resets this temporary registry state. |
| `-nebula-verbose` | all roles | Write debug-level logs. |

Hetzner deployments also use the other `-nebula-cloud-*` options (location, type, image, network, ssh key, firewall, and the provider token). Let `nebula deploy` supply them unless you run the orchestrator yourself. See [Deploy to Hetzner Cloud](/docs/deploy/hetzner) for the supported values.

Unity's standard `-batchmode`, `-nographics`, and `-logFile <path>` options also apply.

A web build has no command line. It reads the same options from the page's query string, without the leading dash, for example `?nebula-name=Player&nebula-connect`.

## Configure one project in nebula.json

Run `nebula init` to create `nebula.json` at the Unity project root. The CLI reads this file for local and cloud defaults.

```json title="nebula.json"
{
  "nebula": "0.1.0",
  "executable": "Nebula",
  "mesh": {
    "workers": 4,
    "minWorkers": 1,
    "maxWorkers": 4,
    "idlePoolSeconds": 0,
    "npcs": 0,
    "dashboardPort": 7080,
    "gatewayPort": 7000
  },
  "deploy": {
    "target": "hetzner",
    "meshName": "nebula-my-game",
    "workers": 4,
    "npcs": 0
  }
}
```

| Key | What it controls |
| --- | --- |
| `nebula` | Records the CLI version that last wrote the file. `nebula init` updates it. |
| `executable` | Sets the base name of builds produced by `NebulaBuild`, such as `Nebula.exe` or `Nebula.x86_64`. |
| `mesh.workers` | Sets the default worker count for `nebula start`. |
| `mesh.minWorkers`, `mesh.maxWorkers` | Set the default autoscaling band for `nebula start`. Leave them out and `--workers` fixes the count. `--min` / `--max` override them, and the mesh starts at the floor. |
| `mesh.idlePoolSeconds` | Sets how long a retired worker stays parked in the idle pool. `0` uses the host's own answer. |
| `mesh.dashboardPort`, `mesh.gatewayPort` | Set the ports used by a local mesh and by deployment firewalls. |
| `mesh.database` | Select where the local orchestrator keeps the control plane and saved entities. Leave it out for `sqlite:Library/Nebula/nebula.db`. |
| `deploy.target` | Selects the deployment target: `hetzner` or `cloud` (see [Deploy to Nebula Cloud](/docs/deploy/cloud)). |
| `deploy.meshName` | Sets the label and name prefix used for cloud resources. |
| `deploy.database` | Selects the deployed orchestrator's database (`postgres://...` or `sqlite:<file on the VM>`). Leave it out to use `nebula config database`, else SQLite on the orchestrator VM. |
| `deploy.workers` | Sets the default worker count for `nebula deploy`. |
| `deploy.workerType`, `deploy.orchestratorType`, `deploy.location` | Override the machine types and region stored in the CLI's machine config. |

The `mesh.npcs` and `deploy.npcs` keys seed a game setting named `npcs`. Nebula does not create non-player characters or assign meaning to this setting. Leave both values at `0` unless your game reads the setting.

## Configure this computer

Run `nebula config` commands to store machine-specific paths and credentials in `~/.nebula-cli/config.json`:

```bash
nebula config source
nebula config unity
nebula config hetzner
nebula config database
nebula config show
```

`nebula config show` masks the saved Hetzner token and the database password. On Unix, the CLI creates the file with permissions `0600`. Set `HCLOUD_TOKEN` to override the saved token and `NEBULA_DATABASE_URL` to override the saved database URL.

Set `NEBULA_CLI_HOME` to move the entire `~/.nebula-cli` directory. The directory also contains the CLI binary, a downloaded SDK checkout when you have not configured a source checkout, and temporary project copies used during builds.
