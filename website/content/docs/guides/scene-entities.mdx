---
title: Scene entities
description: Networking objects that are authored into a scene (doors, lifts, turrets) instead of spawned from a prefab.
---

Most entities are spawned from a prefab: a worker instantiates it, mints an id and announces it, and every other process instantiates the same prefab when the announcement arrives (see [Spawning](/docs/guides/spawning)). A door built into the map is different. It already exists in every process that has the scene loaded, it never moves between containers, and nobody should instantiate a second copy of it. Nebula calls such an object a **scene entity**: a `NetworkIdentity` authored into a scene, which the network *binds* rather than creates.

## Authoring

Put a `NetworkIdentity` and your `NetworkBehaviour`s on the scene object, exactly as you would on a prefab. When the scene is saved, the editor gives the identity a `SceneId`: a random non-zero number, unique within the scene and across every scene open at the time, that stays with the object for good. Prefab assets keep `SceneId` 0; an instance placed in a scene gets its id as an override, so the same prefab can be both spawnable and placed.

The object must be active when its scene loads (an inactive object never runs `Awake`, so it never registers). Anything on it works as on a spawned entity: NetworkVariables, RPCs, `NetworkTick`, sync behaviours, handover state.

```csharp title="ProximityDoor.cs (from the sample)"
[RequireComponent(typeof(NetworkIdentity))]
public sealed class ProximityDoor : NetworkBehaviour
{
    public NetworkVariable<bool> IsOpen = new NetworkVariable<bool>(false);

    public override void NetworkTick(uint tick, float deltaTime)   // authority only
    {
        IsOpen.Value = SomeoneIsNear();
    }

    private void Update()                                         // every copy
    {
        SlideLeavesTowards(IsOpen.Value);
    }
}
```

## Lifecycle

| Moment | What happens |
| --- | --- |
| Scene loads (any role) | The identity initialises itself and registers in [`SceneEntities`](/docs/reference/core/scene-entities). It is *resident* but not spawned: `IsSpawned` is false, `NetId` is 0, no hooks have run. |
| Worker owns the container it stands in | After `NebulaConfig.SceneEntityGraceSeconds` (default 2 s) of holding the lease, the worker spawns it like any entity: id minted, `OnNetworkSpawn` and `OnGainedAuthority` run, the gateway is told. |
| Spawn reaches a client or a neighbouring worker | Instead of instantiating a prefab, the process binds its own copy: the message names the scene id, the registry finds the object, and it takes the net id, epoch, container and variables. If that process has not loaded the cell yet, the spawn waits and binds the moment the cell streams in; variable updates that arrive meanwhile are folded into the waiting record. |
| Lease moves to another worker | An ordinary handover. The new owner's copy is bound by the transfer (or was already a ghost); the old owner's copy becomes a ghost and is eventually forgotten. The grace period exists so the new owner does not spawn a second life before the handover lands. |
| Despawn, ghost expiry, disconnect | The object is **unbound**: `OnNetworkDespawn` runs and it returns to the unspawned state it loaded in, keeping the last replicated values. The GameObject is never destroyed by the network. |
| Cell unloads while bound | A client holds the entity's record and re-binds when the cell comes back. A worker with authority despawns it (a re-lease spawns it again); a ghost is forgotten. |

Because the object stays in its scene's hierarchy, it is never re-parented under a container, and in a partitioned world the streamer moves it with its cell on an origin shift (its cached poses and interpolator follow, as for any entity).

## What it is not

A scene entity is not a way to reach an object across workers without spawning it: the whole point is that exactly one worker simulates it, chosen by the container it stands in, and everyone else receives its state. Nor is it a static id for prefabs; a spawned entity keeps its worker-minted id.

There is no interest management on the spawn itself (the gateway announces every entity to every client), so a map with thousands of scene entities sends thousands of small spawns to a joining client. Variables and RPCs follow the usual rules.
